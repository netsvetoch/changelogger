Вышел минорный релиз [Knip 6.34.0](https://github.com/webpro-nl/knip/releases/tag/knip%406.34.0) — инструмента для поиска неиспользуемых файлов, зависимостей и exports в JavaScript- и TypeScript-проектах. Версия в основном состоит из фиксов: восстановлен отчёт экспортированных типов, используемых только в параметрах приватных функций, добавлена поддержка статических glob-паттернов из `node:fs/promises`, работа с JSDoc-тегами на URL-зависимостях, строгая валидация числовых опций CLI вместо молчаливого `NaN`, а также две важные починки в monorepo-сценариях — workspace-скопные компиляторы и резолвинг Nuxt `#shared`.

Источники: [GitHub Release](https://github.com/webpro-nl/knip/releases/tag/knip%406.34.0), issues [#1950](https://github.com/webpro-nl/knip/issues/1950) и [#1943](https://github.com/webpro-nl/knip/issues/1943), PR [#1977](https://github.com/webpro-nl/knip/pull/1977), [#1975](https://github.com/webpro-nl/knip/pull/1975), [#1997](https://github.com/webpro-nl/knip/pull/1997), [#1991](https://github.com/webpro-nl/knip/pull/1991). Версия `6.34.0` — minor-граница semver; `featured` оставлен `false`.

## Возврат отчёта типов из private-параметров

Первая правка (коммит `3c785f5`) закрывает [регрессию #1950](https://github.com/webpro-nl/knip/issues/1950): начиная с Knip 6.12.0 экспортированный тип, на который ссылается сигнатура функции в том же файле — тип параметра, возврата или generic-аргумент — перестал отчитываться как unused, даже когда функция не экспортирована и ничего за пределами файла его не импортирует. Из шести типов в репродукции отчитывались только `AsLocalAnnotation` и `Unused`.

Суть проблемы была в том, что тип из сигнатуры _экспортированной_ функции теперь намеренно считается частью её публичного API и не помечается как мёртвый. Но для приватной функции это неверно: такой тип не может быть назван ни одним потребителем, и его `export` действительно мёртв. После фикса `AsPrivateParam` снова отчитывается:

```ts
// src/lib.ts
export type AsPrivateParam = { id: string };

function privateFn(p: AsPrivateParam) {} // privateFn не экспортирована

export type Unused = { n: number }; // по-прежнему unused
```

Теперь Knip различает типы, читаемые в приватных (неэкспортированных) сигнатурах, и снова сообщает о них как о неиспользуемых экспортах.

## Поддержка `node:fs/promises` `glob`

PR [#1977](https://github.com/webpro-nl/knip/pull/1977) ([закрывает #1974](https://github.com/webpro-nl/knip/issues/1974)) добавляет поддержку статических glob-паттернов из `node:fs/promises`. Плагин Node.js теперь распознаёт именованные импорты, namespace-импорты и CommonJS-деструктуризацию, включая статические опции `cwd`:

```js
import { glob } from "node:fs/promises"; // зависимость учитывается

for await (const file of glob("src/**/*.ts", { cwd: "packages/a" })) {
  // ...
}
```

```js
const fs = require("node:fs/promises");
const { glob } = fs;
```

```js
const { glob } = await import("node:fs/promises");
```

Раньше модуль, импортируемый подобным образом, мог отчитываться как unused-зависимость. Теперь это распознаётся как реальное использование — с регрессионным покрытием и выделенной фикстурой.

## JSDoc-теги на URL-зависимостях

Коммит `f93ad09` закрывает [issue #1943](https://github.com/webpro-nl/knip/issues/1943): нельзя было подавить JSDoc-тегом (например `@knipignore`) ошибку о нелистинговой (unlisted) зависимости, когда путь содержит `node_modules` в составе URL. Речь про зависимости вида:

```js
// @knipignore
new Worker(new URL("./node_modules/foo/index.js", import.meta.url));
```

Раньше правило, вычислявшее, является ли путь зависимостью внутри `node_modules`, отрабатывало до проверки JSDoc-тега, и тег не мог подавить отчёт. Теперь порядок обработки скорректирован так, что JSDoc-подавление работает для таких URL-зависимостей. Для сравнения: `@knipignore` для unused exports и раньше работал — это была проблема именно URL с `node_modules`.

## Валидация числовых опций CLI вместо `NaN`

PR [#1975](https://github.com/webpro-nl/knip/pull/1975) чинит молчаливый пропуск валидности у `--max-issues` и `--max-show-issues`. Раньше они объявлялись как строки и читались через `Number()` без проверки: `Number("abc")` даёт `NaN`, а всякое сравнение с `NaN` ложно, поэтому строка

```ts
totalErrorCount > Number(args["max-issues"] ?? 0);
```

просто никогда не срабатывала при битом значении. `knip --max-issues=abc` выходил с кодом 0, сколько бы issues ни нашлось — гейт exit-кода переставал гейтить. Реалистичный путь появления — CI-переменная с нечисловым значением.

Теперь добавлен хелпер, который применяется до начала анализа и бросает `ConfigurationError` при невалидном значении:

```ts
export const parseNumericOption = (
  value: string | undefined,
  option: string
) => {
  if (value === undefined) return undefined;
  if (!/^\d+$/.test(value)) {
    throw new ConfigurationError(
      `Option --${option} expects a non-negative integer, got: ${value}`
    );
  }
  return Number(value);
};
```

Регулярка прямо описывает контракт: только неотрицательные целые. Отклоняются не только `abc`, но и отрицательные, дробные, пустая и whitespace-строка. Процесс завершается с кодом 2 с подсказкой `Run knip --help`. Покрыто семью unit-тестами и CLI-тестом, который запускает реальный бинарь с `--max-issues=abc` и проверяет exit code 2.

## Компиляция с workspace-скопными компиляторами

PR [#1997](https://github.com/webpro-nl/knip/pull/1997) ([закрывает #1930](https://github.com/webpro-nl/knip/issues/1930)) исправляет ложные срабатывания в monorepo, где плагины регистрируют workspace-специфичные компиляторы. Раньше компиляторы, зарегистрированные плагинами, хранились проекта-wide по расширению файла, сохраняя лишь первого регистранта. Marko встраивает в компилятор карту «тег → зависимость» из `package.json` конкретного workspace, а Nuxt — auto-import maps из своего `.nuxt`. Так как корневой workspace обрабатывался первым, каждый `.marko`/`.vue`-файл в monorepo компилировался корневым компилятором, и теги/auto-imports, предоставляемые только зависимостями дочерних workspace, не превращались в синтетические импорты → ложные отчёты о неиспользуемых зависимостях, файлах и exports.

Теперь файлы компилируются компилятором того workspace, которому принадлежат:

- `ProjectPrincipal` запоминает dir-скоупную запись для каждой регистрации; lookup выбирает самый длинный подходящий префикс каталога, а для файлов вне какого-либо регистрирующего workspace откатывается на прежнюю глобальную карту по расширению (первый регистрант).
- Регистрируется каждая запись (а не только конфликтные), чтобы порядок разрешения был независим: workspace обрабатываются nested-child-efore-ancestor, и предок, зарегистрировавшийся позже, не должен затенять файлы ребёнка (покрыто фикстурой `marko-workspace-nested`).
- Компиляторы async не трогаются — плагины могут регистрировать только синхронные, а config-уровневые async-компиляторы глобальны.

Второй коммит применяет это к Nuxt-слоям: `registerCompilers` теперь срабатывает и когда у workspace есть сгенерированные `.nuxt`-файлы определений, даже если его манифест — заглушка без зависимостей (конвенция слоёв), чтобы файлы каждого слоя компилировались со своими auto-import maps. Слой без собственного `.nuxt` по-прежнему фолбэчится на корневой компилятор.

Добавлено три фикстуры с тестами, каждая падала до фикса и проходит после: `compilers/marko-workspace`, `compilers/marko-workspace-nested` и `plugins/nuxt-layers`.

## Резолвинг Nuxt `#shared`

PR [#1991](https://github.com/webpro-nl/knip/pull/1991) чинит резолвинг алиаса `#shared` в плагине Nuxt, когда каталог общих файлов переопределён через `dir.shared`. Раньше валидные импорты вида `#shared/utils/value` отчитывались как нерезолвленные, а файлы в кастомном shared-каталоге — как неиспользуемые. Теперь каталог регистрируется как алиас `#shared` вместе с wildcard-алиасом для подпутей:

```ts
const sharedDir = toAbsolute(localConfig.dir?.shared ?? "shared", cwd);
inputs.push(toAlias("#shared", sharedDir));
inputs.push(toAlias("#shared/*", join(sharedDir, "*"), { dir: cwd }));
```

С регрессионным тестом: фикстура с `dir.shared: 'shared-custom'`, файл `shared-custom/utils/value.ts` и server-handler, импортирующий его через `#shared/utils/value`, — импорт больше не отчитывается как нерезолвленный, а файл — как unused.
