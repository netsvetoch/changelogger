Gravity UI выпустила минорный релиз [`@gravity-ui/charts v1.59.0`](https://github.com/gravity-ui/charts/releases/tag/v1.59.0). В выпуске одно новое свойство (auto placement для подписей line-серий) и один багфикс (подписи верхней серии в percent-стеке). Главное по diff:

- `placement` / `placementFallback` в `dataLabels` line-серии — автоподбор позиции подписи с обходом линий и других подписей;
- исправление в `prepareAreaData`: подписи верхней серии percent-стека больше не пропадают и не «мерцают» при ресайзе.

Источник для обзора — GitHub Release [`gravity-ui/charts@v1.59.0`](https://github.com/gravity-ui/charts/releases/tag/v1.59.0), compare [`v1.58.0...v1.59.0`](https://github.com/gravity-ui/charts/compare/v1.58.0...v1.59.0), PR [`#660`](https://github.com/gravity-ui/charts/pull/660) (auto placement) и [`#682`](https://github.com/gravity-ui/charts/pull/682) (фикс percent-стека).

## Auto placement: `placement` и `placementFallback` у data labels line-серий

Раньше data label line-серии всегда рисовался над точкой (жестко сверху). PR [`#660`](https://github.com/gravity-ui/charts/pull/660) добавляет в `dataLabels` две необязательные опции, которые включают единый движок автоподбора позиции. Определение в [`src/core/types/chart/line.ts`](https://github.com/gravity-ui/charts/blob/v1.59.0/src/core/types/chart/line.ts):

```ts
export type LineSeriesDataLabelPlacementPosition =
  "top" | "bottom" | "left" | "right";

export type LineSeriesDataLabelPlacementFallback = "show" | "hide";

export interface LineSeriesDataLabels extends BaseDataLabels {
  /** Какие позиции относительно точки пробовать, в порядке перечисления. */
  placement?: "auto" | LineSeriesDataLabelPlacementPosition[]; // default: ['top']
  /** Что делать, если ни одна позиция не подошла. */
  placementFallback?: LineSeriesDataLabelPlacementFallback; // default: 'show'
}
```

- `placement` — позиции-кандидаты, перебираемые по порядку. Значение `'auto'` пробует встроенный порядок — `top, bottom, left, right`; массив задаёт точный порядок (например `['bottom', 'top']`). По умолчанию — `['top']`.
- `placementFallback` — что делать, когда ни одна позиция не помещается: `'show'` всё равно рисует подпись в первой позиции (тогда допускается пересечение линий и подписей), `'hide'` прячет подпись. По умолчанию — `'show'`.

Важно: движок единый, отдельных режимов нет. Прежнее поведение «всегда над точкой» — это просто дефолтная конфигурация (`['top']` + `show`), которая даёт пиксель-в-пиксель тот же результат. При одной позиции и `show`-fallback движок пропускает все проверки — это быстрый путь и точное воспроизведение старого поведения.

Как это работает: для каждой подписанной точки позиции пробуются по порядку. Сначала бокс подписи сдвигается внутрь области графика; позиция считается подходящей, если сдвинутый бокс не пересекает видимую линию ни одной line-серии (тест «сегмент × бокс» с дешёвым bbox-reject и отсечением Лианга — Барски, бокс дополнительно раздут на половину ширины линии) и не перекрывает уже размещённые подписи (кроме случая `allowOverlap`). Побеждает первая подходящая позиция. Каждая размещённая подпись становится препятствием для последующих, а при конкуренции за одно место побеждает серия, указанная первой в `series.data`.

Интерполированные линии (`monotone`, `cardinal`) обходятся через ту же фабрику кривых, что и рендерер, и сплющиваются в прямые отрезки — геометрия коллизий совпадает с тем, что отрисовано. Размеры подписей измеряются один раз на серию и кэшируются, так как каждый line-layer заново размещает подписи предыдущих серий, используя их как препятствия.

Пример из документации выпуска ([`placement-auto.tsx`](https://github.com/gravity-ui/charts/blob/v1.59.0/docs/examples/src/charts/data-labels/placement-auto.tsx)):

```tsx
const data: ChartData = {
  series: {
    data: [
      {
        type: "line",
        name: "Rising",
        data: [
          { x: 0, y: 30 },
          { x: 1, y: 40 },
          { x: 2, y: 50 },
        ],
        dataLabels: { enabled: true, placement: "auto" },
      },
      {
        type: "line",
        name: "Falling",
        data: [
          { x: 0, y: 50 },
          { x: 1, y: 40 },
          { x: 2, y: 30 },
        ],
        dataLabels: { enabled: true, placement: "auto" },
      },
    ],
  },
  yAxis: [{ min: 0, max: 80 }],
};
```

Фича задокументирована в гайде `docs/diplodoc/pages/guides/series-types/line.md` и снабжена тремя live-примерами (`placement-auto`, `placement-fixed`, `placement-fallback-hide`).

## Фикс: подписи верхней серии percent-стека

PR [`#682`](https://github.com/gravity-ui/charts/pull/682) чинит пропадание и «мерцание» data labels верхней серии в area-сериях со `stacking: 'percent'`. Проблема была в двойной арифметической ошибке:

1. Координата точки накапливалась из пиксельных высот секций ниже неё, каждая из которых округлялась отдельно (`round(yValue, 2)`). Для верхней серии результат математически равен `0` (верхняя граница области), но в double-арифметике выходит `±5e-15` со знаком, меняющимся от точки к точке.
2. Строгая проверка границ без субликсельного допуска отбрасывала такие точки как «вне области», поэтому подпись получала лишь точка с положительным остатком — отсюда и фликер при ресайзе (какие точки выживают, зависело от высоты графика).

Что изменено в `prepareAreaData`:

- **Шум устранён в источнике.** Стек теперь накапливается из неокруглённых высот секций, а координата округляется один раз, уже после применения смещения секции. Ошибки округления больше не накапливаются, и верх percent-стека ложится ровно в `0`. Побочный эффект — секции стыкуются без зазора: раньше `y` нижней секции и `y0` следующей могли различаться до `0.0078px`, теперь различие ровно `0`.
- **Проверка границ получила субликсельный допуск.** `createIsOutsideBounds` теперь разрешает полпикселя с каждой стороны — тот же slack, что всегда использовал `markHiddenPointsOutOfYRange` (оба делят константу `PLOT_BOUNDS_PIXEL_TOLERANCE`). Это убирает асимметрию, когда точка на краю области была «достаточно хороша» для линии, но не для её подписи, и покрывает тот же класс дефекта для line и scatter (у них общий `preparePointDataLabels`), а также перестаёт помечать маркеры таких точек как `clipped`.

Строгая проверка в `useChartInnerHandlers` (обработчики указателя) оставлена намеренно — там нет масштабного округления, которое надо компенсировать.

## Что проверить при обновлении

- Миграции не требуется: `placement` / `placementFallback` — новые необязательные поля; без них подписи line-серий рендерятся как раньше (`['top']` + `show`), поведение пиксель-в-пиксель то же. Подписи/маркеры верхней серии в percent-стеке теперь не пропадают при определённой высоте графика и не «прыгают» при ресайзе.
- Если вы вручную настраивали позицию подписей (например всегда снизу), теперь вместо своих вычислений можно задать `placement: ['bottom']`; а чтобы запретить пересечение линий — `placementFallback: 'hide'`.
- Side-effect фикса: секции в стеке стыкуются без зазора до `0px` (раньше возможен зазор до `0.0078px`).
