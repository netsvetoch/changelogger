Вышел минорный релиз [Knip 6.32.0](https://github.com/webpro-nl/knip/releases/tag/knip%406.32.0) — инструмента для поиска неиспользуемых файлов, зависимостей и exports в JavaScript- и TypeScript-проектах. В этой версии три новых plugin (`borp`, `tsd`, `pre-commit`), расширенный разбор CLI/config у Mocha, Rollup, Jest и Playwright, корректнее обработка quoted args в npm-scripts, а также несколько точечных fix’ов dependency graph: wildcard subpath imports, built-ins по module specifier и absolute-path binaries.

Источники: [GitHub Release](https://github.com/webpro-nl/knip/releases/tag/knip%406.32.0), [compare 6.31.0…6.32.0](https://github.com/webpro-nl/knip/compare/knip%406.31.0...knip%406.32.0) (17 коммитов), PR [#1918](https://github.com/webpro-nl/knip/pull/1918), [#1919](https://github.com/webpro-nl/knip/pull/1919), [#1922](https://github.com/webpro-nl/knip/pull/1922). Версия `6.32.0` — minor-граница semver; `featured` оставлен `false`.

## Плагин `borp`

Plugin регистрируется как `borp` (enabler — dependency `borp`, runner [mcollina/borp](https://github.com/mcollina/borp) поверх Node test runner).

```ts
const enablers = ["borp"];
const config = [".borp.yaml", ".borp.yml"];
const entry = ["**/*.test.{js,mjs,cjs,ts,mts,cts}"];
```

`resolveConfig` читает YAML-конфиг:

- `reporters` — custom reporters через `toDeferResolve`; built-in `spec` / `tap` / `dot` / `junit` / `lcov` / `gh` игнорируются;
- `files` — entry-паттерны (fallback — дефолтный `entry`).

Reporter вида `path:dest` режется до имени до `:`, чтобы `./reporters/plum.mjs:out.txt` считался файлом reporter’а, а не literal path с суффиксом.

CLI args plugin:

- boolean: `coverage` (`-C`), `watch`, `only`, `no-timeout`, `expose-gc`, `check-coverage`, `coverage-html`;
- alias: `reporter`/`-r`, `pattern`/`-p`, `ignore`/`-i`, `timeout`/`-t`, `concurrency`/`-c`, `coverage-exclude`/`-X`;
- `resolveInputs` поднимает custom `--reporter` и positional/`--pattern` в entries.

Fixture `plugins/borp`:

```yaml
# .borp.yaml
reporters:
  - "@jsumners/line-reporter"
files:
  - "checks/**/*.check.mjs"
```

```json
{
  "scripts": {
    "test": "borp --coverage 'spec/**/*.spec.mts'",
    "test:ci": "c8 borp --reporter ./reporters/plum.mjs:out.txt --reporter gh"
  },
  "devDependencies": {
    "@jsumners/line-reporter": "*",
    "borp": "*",
    "c8": "*"
  }
}
```

Интеграционный тест: `processed/total: 3` (spec + check + custom reporter) без unused deps.

В schema добавлен ключ:

```json
"borp": {
  "title": "borp plugin configuration (https://knip.dev/reference/plugins/borp)",
  "$ref": "#/definitions/plugin"
}
```

## Плагин `tsd`

Plugin для [tsd](https://github.com/tsdjs/tsd) (type-definition tests). Enabler — `tsd`.

```ts
const config = ["package.json"];
const entry = ["*.test-d.{ts,tsx}", "test-d/**/*.test-d.{ts,tsx}"];
```

`resolveConfig` смотрит секцию `tsd` в `package.json` (`TsdConfig`):

```ts
export type TsdConfig = {
  directory?: string;
  testFiles?: string[];
};
```

- `testFiles` → entry as-is;
- `directory` → `*.test-d.{ts,tsx}` + `${directory}/**/*.test-d.{ts,tsx}`;
- иначе дефолтный `entry`.

CLI: `--files`/`-f`, `--typings`/`-t`; positional directory → `${dir}/**/*.test-d.{ts,tsx}`.

Fixture:

```json
{
  "scripts": {
    "test:types": "tsd",
    "test:assertions": "tsd --files 'assertions/*.test-d.ts'"
  },
  "tsd": { "directory": "type-checks" },
  "devDependencies": { "tsd": "*" }
}
```

Тест ожидает `processed/total: 2` (`type-checks/guava.test-d.ts` + `assertions/papaya.test-d.ts`).

## Плагин `pre-commit`

Для [fastify/pre-commit](https://github.com/fastify/pre-commit) / `@fastify/pre-commit`. Plugin **root-only** и не сканирует config-файлы: если пакет есть в `dependencies`/`devDependencies` root manifest, он помечается used через `toDependency`.

```ts
const packages = ["pre-commit", "@fastify/pre-commit"];
const isRootOnly = true;

const resolve: Resolve = options => {
  const { dependencies, devDependencies } = options.manifest;
  const inputs = [];
  for (const name of packages)
    if (dependencies?.[name] || devDependencies?.[name])
      inputs.push(toDependency(name));
  return inputs;
};
```

Зачем отдельный plugin: `pre-commit` подключается side-effect’ом install hooks и полем `"precommit": ["lint"]` в `package.json`, без import в source — без явного mark-as-used Knip считал бы dependency unused. Fixture:

```json
{
  "precommit": ["lint"],
  "scripts": { "lint": "node checks/style.js" },
  "devDependencies": { "@fastify/pre-commit": "*" }
}
```

`processed/total: 1` (файл `checks/style.js` через script `lint`).

## Mocha: entries из script arguments

Plugin Mocha получил полноценный `args.resolveInputs`. Раньше entry шли в основном из config (`spec` / `require`); теперь CLI вроде:

```json
{
  "scripts": {
    "test:integration": "mocha --recursive integration",
    "test:e2e": "mocha \"e2e/*.e2e.mjs\" \"smoke/*.smoke.mjs\""
  }
}
```

разбирается так:

1. positional / `--spec` / `--file` — если путь **директория**, строится glob `dir/**/*.ext` при `--recursive`, иначе `dir/*.ext`;
2. extensions из `--extension` (comma-separated, с/без точки), default `js,cjs,mjs`;
3. `--ignore` → negative entry `!pattern`.

Плюс полный набор boolean/alias Mocha (`bail`/`-b`, `grep`/`-g`, `reporter`/`-R`, `timeout`/`-t`, `watch`/`-w`, `node-option`/`-n`, …) и `config: ['config']`.

Fixture после релиза: `processed/total: 6` (config-spec + hooks + integration nested + e2e/smoke).

## Rollup: `--config` как plugin configuration

В `args` Rollup добавлено:

```ts
string: ["config"],
config: ["config"],
args: (args: string[]) =>
  args
    .filter(
      (arg, index) =>
        !(arg === "--config" && (args[index + 1] === undefined || args[index + 1].startsWith("-")))
    )
    .map(arg => (arg.startsWith("--watch.onEnd") ? `--_exec${arg.slice(13)}` : arg)),
```

Эффект:

- `rollup --config configs/rollup.web.config.mjs` → Knip резолвит **указанный** config file как plugin config (не только дефолтный `rollup.config.{js,cjs,mjs,ts}`);
- bare `rollup --config` / `rollup --config -w` (без значения) **не** превращается в ложный config path — flag отбрасывается, остаётся default discovery;
- remap `--watch.onEnd…` сохранён (обход бага minimist с точками в длинных flags).

Fixture scripts:

```json
{
  "build": "rollup",
  "build:web": "rollup --config configs/rollup.web.config.mjs",
  "build:watch": "rollup --config -w"
}
```

Тест: `processed/total: 5`, unlisted plugins из AST config (`rollup-plugin-terser`, `@rollup/plugin-node-resolve`, …).

## Jest: `babel-jest` `configFile`

В `resolveDependencies` для transform-пары `["babel-jest", options]`:

```ts
if (isBabelJest(transformer)) {
  transform.push(...getDependenciesFromConfig(transformer[1]));
  const { configFile } = transformer[1];
  if (typeof configFile === "string")
    transform.push(
      toConfig(
        "babel",
        rootDirRe.test(configFile)
          ? configFile
          : toAbsolute(configFile, options.cwd)
      )
    );
}
```

Раньше Babel presets/plugins из inline options `babel-jest` уже поднимались, но отдельный `configFile` не уходил в Babel plugin как config input — файл и его deps могли выглядеть unused.

Fixture:

```json
{
  "transform": {
    "^.+\\.jsx?$": ["babel-jest", { "configFile": "./configs/babel.config.js" }]
  }
}
```

`babel.config.js` с `@babel/preset-env` / `babel-plugin-macros` удерживается; тест `processed/total: 1` без dependency issues.

## Playwright: `.cjs` / `.cts` / `.mts` configs

Однострочный, но практичный fix (#1919):

```ts
// было
const config = ["playwright.config.{js,ts,mjs}"];
// стало
const config = ["playwright.config.{js,cjs,mjs,ts,cts,mts}"];
```

Fixture дополнен `playwright.config.cjs|cts|mts` и reporters `.cjs/.cts/.mts`; counters `3 → 9`.

## Node test runner через `c8`

В `getScriptCommands` `c8` добавлен в `spawningBinaries` рядом с `cross-env` и `retry-cli`:

```ts
const spawningBinaries = new Set(["c8", "cross-env", "retry-cli"]);
```

Скрипт `"test": "c8 node --test"` разворачивается в `{ binary: "node", args: ["--test"] }`, после чего срабатывает node-test-runner plugin и подхватывает `**/*.{test,spec}.*` / default test files. Без unwrap Knip видел только binary `c8` и не включал test entry.

Fixture: dev-mode `processed/total: 2` (`index.js` + `index.test.js`), production — `1`.

## Quoting: Word’ы через binary resolvers

Коммит «Thread script words through resolvers to preserve quoting» меняет контракт resolvers:

```ts
export type ScriptArg = string | Word;
export type BinaryResolver = (
  binary: string,
  words: Word[],
  options: BinaryResolverOptions
) => Input[];
```

`parseArgs` принимает `string | Word` и достаёт `.value`; `argsFrom` / `argsAfter` / `toWordArgs` / `expandScript` прокидывают Word-объекты unbash, а не только «голые» строки после split.

Зачем: значения вроде `--onlyAllow="0BSD;Apache-2.0;…;MIT;"` или `--filter="unit;fast"` раньше после unwrap spawning binary/`pnpm exec`/`yarn` могли резаться по `;` или пробелам и порождать **ложные binaries** (`MIT`, `Apache-2.0`) или ломать forwarded args.

Тесты:

```ts
// scripts
getScriptCommands('cross-env FLAGS="-a;-b" bun test --filter="unit;fast"');
// → [{ binary: "bun", args: ["test", "--filter=unit;fast"] }]

// getInputsFromScripts
('npx license-checker --production --onlyAllow="0BSD;Apache-2.0;BSD-2-Clause;ISC;MIT;"');
// → [toBinary("license-checker")]  // без MIT/Apache как binaries

('pnpm exec program --onlyAllow="0BSD;MIT" --report="summary out"');
// → [toBinary("program")]
```

В GitHub Actions fixture явно: `assert(!issues.binaries[…]['MIT'])`, `assert(!issues.binaries[…]['Apache-2.0'])` для шага с `npx license-checker --onlyAllow="…"`.

## Fix: wildcard subpath-import aliases (#1918)

`getManifestImportDependencies` раньше клал в used-deps **целиком** export target (`@scope/fruit/*`), из-за чего package name не матчился и sibling workspace dep через `#alias/*` → `pkg/*` считался unused.

```ts
// было
if (!item.startsWith(".") && !item.startsWith("!")) dependencies.add(item);

// стало
if (item.startsWith(".") || item.startsWith("!")) continue;
const packageName = getPackageNameFromModuleSpecifier(item);
if (packageName) dependencies.add(packageName);
```

Fixture monorepo:

```json
// packages/consumer/package.json
{
  "imports": { "#fruit/*": "@scope/fruit/*" },
  "dependencies": { "@scope/fruit": "*" }
}
```

```ts
import { apple } from "#fruit/index.js";
```

`@scope/fruit` — used; `issues.dependencies` / `unlisted` пустые.

## Fix: built-ins по module specifier (#1925)

`DependencyDeputy.maybeAddReferencedExternalDependency` теперь **обязан** получать `specifier` и проверяет built-in так:

```ts
if (specifier.startsWith("node:") || isBuiltin(specifier)) return true;
```

раньше `isBuiltin(packageName)`: bare `punycode` (npm-пакет с именем бывшего/существующего Node builtin) мог ошибочно считаться built-in и не учитываться как dependency usage. Fixture добавляет `import 'punycode/'` + dep `punycode` → dependency used, `node:*` по-прежнему не unlisted.

## Fix: absolute-path script tokens (#1928)

Fallback binary resolver:

```ts
const bin =
  binary.startsWith(".") || (binary.includes("/") && !isAbsolute(binary))
    ? toEntry(binary)
    : isValidBinary(binary)
      ? toBinary(binary)
      : undefined;
```

- `target/release/mytool` → entry (relative path-shaped);
- `/opt/example-tool` → **не** entry и не binary issue.

Раньше любой token с `/` шёл в `toEntry`, включая absolute paths из CI/ops scripts.

## VS Code extension: настоящий restart LS (#1923)

В `vscode-knip` команда restart:

```ts
// было
await client.sendRequest(REQUEST_RESTART);
// стало
await client.restart();
```

`LanguageClient.restart()` перезапускает process language server, а не только внутренний request — после bump локальной версии `knip` в `node_modules` diagnostics подтягивают новый version string. Добавлены integration fixture `version-bump` и wait-helper в extension tests.

## Кому обновляться

Имеет смысл ставить 6.32.0, если:

1. используете **borp**, **tsd** или **@fastify/pre-commit** / **pre-commit** — без новых plugins deps/files из их config/CLI часто выглядели unused;
2. гоняете **Mocha** с directory/`--recursive`/`--extension` в npm-scripts, **Rollup** с `rollup --config path`, **Jest** + `babel-jest` `{ configFile }`, **Playwright** с `.cjs/.cts/.mts` config;
3. scripts завёрнуты в **`c8 node --test`** — test files начнут попадать в graph;
4. в CI есть `npx license-checker --onlyAllow="…;MIT;…"` или похожие quoted multi-value flags — уйдут false-positive binaries;
5. monorepo с `"imports": { "#x/*": "@scope/pkg/*" }` — sibling package перестанет быть false unused dependency;
6. в dependencies есть bare-имена вроде `punycode`, которые пересекаются с Node builtins;
7. scripts ссылаются на absolute binaries (`/usr/local/bin/…`) — они больше не станут ложными entries;
8. пользуетесь VS Code extension и `knip.restart` после обновления knip.

## Обновление

```bash
pnpm add -D knip@6.32.0
# или
npm i -D knip@6.32.0

pnpm knip
```

После обновления имеет смысл перепрогнать полный `knip` и сверить:

1. новые entry из borp/tsd/mocha/rollup CLI — не «ожили» ли ранее ignored test/config files;
2. pre-commit package больше не unused (если он только в root manifest);
3. исчезли ли ложные binaries из quoted `--onlyAllow` / похожих flags в Actions;
4. wildcard `#alias/*` → `@scope/pkg/*` держит dependency;
5. absolute-path tokens в scripts не создают file issues.
