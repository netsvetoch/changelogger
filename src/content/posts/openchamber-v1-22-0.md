[OpenChamber](https://github.com/openchamber/openchamber) выпустил минорный релиз [`v1.22.0`](https://github.com/openchamber/openchamber/releases/tag/v1.22.0) — релиз про интеграции и переключение репозиториев. Главное: **первая сторонняя интеграция — Linear** (подключение воркспейса, просмотр и фильтрация issues, старт сессии или ворктри прямо из issue), **локальный TTS и macOS `say` подбирают голос под язык ответа**, а **проекты с несколькими репозиториями наконец можно переключать прямо из Git-таба**.

Основа статьи — GitHub Release [`v1.22.0`](https://github.com/openchamber/openchamber/releases/tag/v1.22.0), compare [`v1.21.0...v1.22.0`](https://github.com/openchamber/openchamber/compare/v1.21.0...v1.22.0) (381 коммит) и ключевые PR/коммиты: Linear OPE-296 [#3235](https://github.com/openchamber/openchamber/pull/3235), голос по языку [`a32d0ef`](https://github.com/openchamber/openchamber/commit/a32d0ef3), переключение репозиториев [`0ed62a1`](https://github.com/openchamber/openchamber/commit/0ed62a1b), возврат контекста при откате [`5481b3a`](https://github.com/openchamber/openchamber/commit/5481b3a0).

## Первая интеграция с Linear: from issue to session

В релизе появился **Linear-коннектор для старта работы прямо из issue** ([OPE-296: Add linear integration for starting sessions from issues, #3235](https://github.com/openchamber/openchamber/pull/3235), спасибо @AlexKutas). Подключение — через **Settings → Integrations**: после OAuth можно хранить **несколько воркспейсов** и переключать текущий, сопоставляя дефолтный проект и каждую Linear-команду с директорией OpenChamber.

Что можно делать:

- **правый рельс** показывает issues текущего воркспейса с фильтрами по статусу, приоритету, исполнителю и команде; открыв карточку, можно менять статус или закрывать issue;
- из карточки или из **New Worktree** запускается сессия из issue — ровно так же, как раньше из GitHub issue: авто-создаётся ветка вида `issue-OPE-296-…` и ворктри;
- **чат может прикрепить issue к следующему сообщению** — пункт `Link Linear Issue` появляется в меню вложений композера рядом с `Link GitHub Issue` и `Link GitHub PR`;
- сессия, запущенная из issue или из её ворктри, **пишет комментарии на Linear** (started/completed/failed) со ссылкой обратно в сессию. Прикрепить issue из чата — таких комментариев не постится.

Под капотом OAuth идёт через hosted-брокер `https://api.openchamber.dev/v1/oauth/linear/callback` (PKCE-верификатор и токены брокер никогда не видит — обмен кодом происходит локально на сервере). Для self-host можно переопределить `OPENCHAMBER_LINEAR_BROKER_URL` / `linearBrokerUrl` или задать `OPENCHAMBER_LINEAR_REDIRECT_URI` / `linearRedirectUri` для собственного Linear-приложения. Зарегистрированные данные — токены и mapping — хранятся в data-директории с правами `0o600` и атомарной записью (`linear-auth.json`, `linear-mapping.json`, `linear-session-status.json`), причём mapping **не удаляется при отключении**.

Curious поле: в **VS Code** integration намеренно не работает — `RuntimeAPIs.linear` там опущен, а UI скрыт, так что никакого «фейкового» состояния нет.

## Голос, который говорит на языке ответа

Раньше text-to-speech читал ответ одним и тем же голосом независимо от языка текста. Теперь оба провайдера подстраиваются ([`feat(voice): match local and macOS voices to the language of the text`](https://github.com/openchamber/openchamber/commit/a32d0ef3)):

- **зависимость-free детектор языка** (по скрипту, маркерным символам и функциональным словам) определяет язык сообщения один раз;
- с новой настройкой **«Match the voice to the language of the text»** локальный провайдер переключается на каталожную модель нужного языка — **Kokoro** для `zh`/`en` и **Piper-модели для 12 языков**, которые скачиваются при первом использовании как и обычная модель;
- macOS `say` переключается на установленный голос, чей локаль совпадает с языком;
- **voice-пикер в настройках теперь перечисляет голоса всех установленных моделей**, а настройки показывают, какие языковые модели уже на диске.

## Проекты с несколькими репозиториями

Проекты, содержащие **несколько репозиториев**, больше не застревают на одной корневой директории ([`fix(git): resolve blank nested-repo surfaces; add repository pickers`](https://github.com/openchamber/openchamber/commit/0ed62a1), спасибо @jaygupta17). Переключатель репозиториев из хидера Git вынесен в общий компонент `NestedRepoPicker` и смонтирован в diff-тулбаре, в pull-request-вью, в хидере walkthrough и в хидере мобильных Changes.

Изменение касается и логики валидации: раньше для поверхностей PR/walkthrough/мобильных Changes «гейт» оставался включённым вечно (корень не был Git-репозиторием), и вью рендерили пустоту. Теперь состояния резолюции показываются только пока рабочая директория **не доказана репозиторием**, как в GitView. Выбранный репозиторий **общий для корня** — diff, pull-request, walkthrough, мобильные Changes и work status следуют за одним выбором.

## Чат: стабильный скролл, возврат контекста и честный статус

- **Сессии, открытые из сайдбара, приземляются на последнее сообщение**, а переключение сессий больше не вызывает скачков, частичного рендера, crossfades или сдвигов заголовков вкладок.
- **Откат вернул прикреплённый контекст в композер** ([`fix(chat): restore a message's attached context on revert and fork`](https://github.com/openchamber/openchamber/commit/5481b3a)): раньше review-комментарии, цитаты, терминальные выделения и аннотации «съедались» при отправке и не возвращались. Теперь при revert или fork сообщения вся его контекст-подвязка возвращается обратно.
- Автодополнение команд, скиллов и файлов в чате без проекта **больше не использует ранее выбранный проект**.
- **Остановленные и неотвеченные ходы объясняют, что произошло**: статусный отчёт включает последние ошибки сессии, отправки и управляемого OpenCode, плюс пути к логам.

## Ещё изменения этого релиза

- **GitHub:** подключение аккаунта переехало в **Settings → Integrations**; панель pull-request получила элементы управления аккаунтом, а её иконка на контекстном рельсе появляется только при подключении. Это часть общего переноса «интеграционных» настроек на страницу Integrations (там же теперь живёт и Linear).
- **Files:** `Ctrl/Cmd+F` открывает поиск в Markdown-превью, даже когда превью не в фокусе.
- **Git:** коммит-граф больше не оставляет разрыв «полосы» (lane gap), когда одна и та же ветка слита дважды (спасибо @Naputt1).
- **Settings:** **темы запоминаются на каждую инстанцию OpenChamber** — окна, подключённые к разным инстанциям, сохраняют собственную тему (спасибо @kydorn).
- **Scheduled tasks:** настройки Goal, Auto-accept и других задач сохраняются, когда старые сборки OpenChamber используют общий конфиг проекта.
- **Desktop:** на Windows и Linux кнопка закрытия достигает верхнего правого угла и следует за темой при наведении (спасибо @kydorn).

Как и раньше, OpenChamber работает поверх OpenCode и поставляется как open-source web/desktop-интерфейс к нему. Полный список изменений — в [release notes v1.22.0](https://github.com/openchamber/openchamber/releases/tag/v1.22.0).
