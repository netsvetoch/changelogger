[`pi`](https://github.com/earendil-works/pi) выпустил minor-релиз [`v0.83.0`](https://github.com/earendil-works/pi/releases/tag/v0.83.0). Самое прикладное изменение для автоматизации — CLI теперь может выдать уже настроенный credential внешнему клиенту, не заставляя скрипт читать `auth.json` или самостоятельно обновлять OAuth token. Одновременно `/login openrouter` перестаёт зависеть от loopback callback, расширения получают фактический model scope сессии, а bundled TypeBox обновлён до 1.3.7 с удалением старых API.

Источники: GitHub Release [`earendil-works/pi@v0.83.0`](https://github.com/earendil-works/pi/releases/tag/v0.83.0), сравнение [`v0.82.0...v0.83.0`](https://github.com/earendil-works/pi/compare/v0.82.0...v0.83.0), документация тега для [OpenRouter](https://github.com/earendil-works/pi/blob/v0.83.0/packages/coding-agent/docs/providers.md#openrouter) и [Extension Context](https://github.com/earendil-works/pi/blob/v0.83.0/packages/coding-agent/docs/extensions.md#ctxmodelregistry--ctxmodel--ctxthinkinglevel--ctxscopedmodels), а также PR [#7168](https://github.com/earendil-works/pi/pull/7168), [#7114](https://github.com/earendil-works/pi/pull/7114), [#7158](https://github.com/earendil-works/pi/pull/7158), [#7191](https://github.com/earendil-works/pi/pull/7191), [#7151](https://github.com/earendil-works/pi/pull/7151), [#7272](https://github.com/earendil-works/pi/pull/7272) и [#7243](https://github.com/earendil-works/pi/pull/7243).

## `pi auth`: credential в stdout для другого клиента

Появились две команды: `pi auth print-api-key` для provider с API key и `pi auth print-bearer-token` для OAuth provider. Они печатают **только значение credential в stdout**: это позволяет передать его в процесс, который ожидает переменную окружения или заголовок, не разбирая внутренний формат Pi.

```bash
# API key из настроенного provider
pi auth print-api-key --provider openai --model gpt-5.5

# OAuth bearer token для внешнего клиента
pi auth print-bearer-token --provider openai-codex --model gpt-5.5
```

`--model` обязателен: Pi разрешает credential для конкретной пары provider/model. `--provider` можно не писать, только когда по модели и сохранённым credentials находится ровно один вариант; при нескольких кандидатах команда требует выбрать provider явно. Нельзя подменить источник через `--api-key`, передать prompt, файлы или неизвестные flags — это отдельная узкая команда экспорта, а не запуск агента.

Для bearer token есть `--min-expiry <duration>` с единицами `ms`, `s`, `m` или `h`; default — `30m`:

```bash
TOKEN="$(pi auth print-bearer-token \
  --provider openai-codex \
  --model gpt-5.5 \
  --min-expiry 1h)"

curl -H "Authorization: Bearer $TOKEN" https://example.internal/v1/models
```

Если OAuth credential близок к окончанию срока, Pi обновляет и сохраняет его по обычному пути auth resolution. Базовое окно обновления для OAuth теперь составляет пять минут, а bearer-export после refresh проверяет запрошенный minimum validity: token, который всё ещё заканчивается слишком рано, не будет молча выдан внешнему процессу. `print-api-key`, напротив, не выдаёт OAuth credential, а `print-bearer-token` не маскирует API-key provider под bearer token.

## OpenRouter login работает через SSH и в контейнере

В 0.82.0 Pi добавил PKCE-вход OpenRouter, но завершение авторизации ожидало loopback server. При `pi` на удалённой машине браузер пользователя не может обратиться к `127.0.0.1` этого хоста, поэтому flow был неосуществим без port forwarding.

Теперь после `/login openrouter` и выбора **Sign in with OpenRouter** можно вставить в prompt финальный redirect URL либо один authorization code. Pi обменивает его с тем же PKCE verifier, который создал для browser flow. Loopback callback по-прежнему работает; если callback уже принят, он имеет приоритет над вставленным значением, поэтому два параллельных способа не перебивают один обмен.

```text
/login openrouter
# открыть URL в локальном браузере, пройти авторизацию
# вставить финальный redirect URL или code в Pi на SSH-хосте
```

Это дополняет, а не удаляет вариант **Use an API key** с `OPENROUTER_API_KEY`. Документация релиза также подтверждает, что результат OAuth flow — контролируемый пользователем OpenRouter API key, расходующий OpenRouter credits.

## Claude Opus 5 через GitHub Copilot

Каталог GitHub Copilot получил `claude-opus-5`. Pi ведёт его через Anthropic Messages API, включает adaptive thinking и принудительно относит модель к Copilot extended-context models с окном **1M tokens**. Это не зависит от того, успели ли обновиться upstream metadata.

Для Copilot-специфичного минимального reasoning level добавлен override `{ minimal: "low" }`, такой же по модели, как у `claude-opus-4.7` и `claude-opus-4.8`. Если Copilot отвечает «model not supported», документация Pi направляет сначала включить модель в VS Code: Copilot Chat → model selector → выбрать модель → **Enable**.

## Расширения видят именно scope текущей сессии

`ExtensionContext` получил readonly `ctx.scopedModels`. Это не полный глобальный каталог `ctx.modelRegistry.getAvailable()`, а тот же resolved набор, который показывает `/scoped-models`: результат `--models` и `enabledModels`, сопоставленных с catalog по `provider/modelId` либо bare `modelId` через minimatch.

```ts
pi.registerCommand("my-model-picker", {
  handler: async (_args, ctx) => {
    for (const { model, thinkingLevel } of ctx.scopedModels) {
      console.log(model.provider, model.id, thinkingLevel);
    }
  },
});
```

Элемент имеет форму `{ model, thinkingLevel? }`; `thinkingLevel` задан только когда pattern его закрепил, например `anthropic/*:high`. Пустой массив означает отсутствие model scoping, то есть доступны все модели. Это позволяет extension сделать selector с той же границей, что и встроенный UI, вместо повторной реализации логики scope.

## Потоковые сообщения: `pending` и исходная причина остановки

В публичный `StopReason` добавлено значение `"pending"` для partial assistant message во время streaming. Важно не сохранять его как итог: документация session format прямо указывает, что terminal `done`/`error` должен заменить `pending` финальной причиной, поэтому в JSONL сессии этого значения быть не должно. Stream, закончившийся без причины, теперь трактуется как ошибка, а не как успешный ответ.

У `AssistantMessage` появился optional `rawStopReason?: string`. Pi сохраняет исходную provider-причину у потоков Google, Anthropic, Amazon Bedrock, Mistral и OpenAI, одновременно оставляя нормализованный `stopReason`. Поэтому integration может отличить, например, успешный `stop` от провайдерского `guardrail_intervened` или Gemini `SAFETY`, не пытаясь извлечь деталь из текста ошибки. Неизвестные terminal reasons больше не выглядят как нормальный stop: в частности, Mistral переводит их в provider error.

## Breaking change: TypeBox 1.3.7 в bundled aliases

Pi обновил bundled TypeBox aliases до `1.3.7`. Из них удалены deprecated API: `Type.Base`, `Type.Awaited`, `Type.Promise`, `Type.AsyncIterator`, `Type.Iterator`, `Type.Options` и `Value.Mutate`. Это breaking change именно для extensions, которые импортировали эти символы через предоставляемый Pi TypeBox: до обновления стоит найти такие обращения и перейти на поддерживаемые TypeBox API.

Вместе с этим обновление исправляет compiled validation tool arguments, где schema допускает `null` наряду с массивом: array-specific keywords теперь не применяются к nullable значению. То есть обновлять стоит не только ради совместимости aliases — это также устраняет ошибку валидации у tools с nullable array parameters.

## Что проверить при обновлении

- Скриптам, которым нужен credential Pi, лучше перейти на `pi auth print-api-key` или `pi auth print-bearer-token`, не читая `auth.json` напрямую; для долгой внешней операции задайте её реальный minimum через `--min-expiry`.
- При запуске по SSH повторите `/login openrouter`: port forwarding больше не обязателен, достаточно вставить redirect URL или code.
- Авторам extensions стоит использовать `ctx.scopedModels` для picker-а и проверить TypeScript на удалённые TypeBox aliases.
- Потребителям streaming API следует обрабатывать `pending` только как промежуточное состояние и, если нужна диагностика провайдера, читать `rawStopReason` рядом с нормализованным `stopReason`.
