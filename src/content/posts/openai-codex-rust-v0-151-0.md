OpenAI выпустила [`rust-v0.151.0`](https://github.com/openai/codex/releases/tag/rust-v0.151.0) — очередной minor-релиз Codex, в котором центр тяжести пришёлся на MCP и плагины. Расширения получили долгожданную точку перехвата результатов MCP-инструментов, старт optional MCP-серверов стал конфигурируемым по задержке, каталоги плагинов начали уважать пер-repository настройки, а remote-сэндбокс и учёт токенов стали заметно строже.

Ниже — разбор GitHub Release и связанных PR: [`#41199`](https://github.com/openai/codex/pull/41199), [`#41202`](https://github.com/openai/codex/pull/41202), [`#41208`](https://github.com/openai/codex/pull/41208), [`#41192`](https://github.com/openai/codex/pull/41192), [`#41195`](https://github.com/openai/codex/pull/41195), [`#41206`](https://github.com/openai/codex/pull/41206), [`#41196`](https://github.com/openai/codex/pull/41196), [`#41204`](https://github.com/openai/codex/pull/41204), [`#41207`](https://github.com/openai/codex/pull/41207), [`#41209`](https://github.com/openai/codex/pull/41209), [`#41183`](https://github.com/openai/codex/pull/41183).

## Расширения могут обрабатывать результаты MCP-инструментов

Главная фича для разработчиков расширений. PR [`#41202`](https://github.com/openai/codex/pull/41202) добавляет в интерфейс расширений новый хук:

```rust
ToolLifecycleContributor::on_mcp_tool_result
```

Хук получает доступ к контексту выполненного MCP-инструмента, переписанным аргументам, data-store расширения и **изменяемому результату сервера**. Он выполняется до публикации MCP-комплешена и до подготовки результата для модели — то есть расширение может как инспектировать, так и полностью заменять результат, включая ошибки. Тесты покрывают неизменные, заменённые и ошибочные результаты для прямых MCP-вызовов, а также заменённые и ошибочные результаты в Code Mode; комплешен ждёт обработки результата, и обработанный результат утекает и в completion-события, и в последующий ввод модели.

## Настраиваемая задержка старта optional MCP-серверов

Раньше задержка, в течение которой Codex ждал инструменты от optional MCP-серверов, была жёсткой константой. PR [`#41199`](https://github.com/openai/codex/pull/41199) делает её конфигурируемой через новую опцию:

```toml
mcp_optional_startup_grace_ms = 2000   # задержка для optional MCP-серверов (по умолчанию 1000)
```

- Значение по умолчанию — `1000` мс: то же поведение, что было раньше.
- Значение `0` отключает общую задержку — тогда optional-серверы используют свой пер-server `startup_timeout_sec`, объявленный в конфигурации MCP.
- Обновления задержки применяются и при runtime-refresh конфигурации MCP: закешированные сроки старта сбрасываются, когда сконфигурированное значение меняется.

Это удобно, когда у вас много managed/optional MCP-серверов — можно либо дать им больше времени на поднятие (медленные серверы), либо отключить общий grace и полагаться на точные таймауты каждого сервера.

## Каталоги плагинов: per-repository конфигурация и ошибки marketplace

PR [`#41208`](https://github.com/openai/codex/pull/41208) чинит каталоги плагинов (`plugin/list`, `plugin/installed`). Раньше конфигурация каталога резолвилась без учёта конкретной рабочей директории. Теперь:

- Для каждого запрошенного `cwd` загружается эффективная конфигурация плагинов.
- Локальные marketplaces объединяются в порядке запросов; для дубликатов сохраняется первый источник, но состояние `installed`/`enabled` мержится между репозиториями.
- Невалидная конфигурация проекта больше не роняет каталог целиком: она отдаётся через `marketplaceLoadErrors`, при этом рабочие локальные каталоги и глобально включённые remote-каталоги продолжают отображаться.
- Объединённый marketplace-контекст используется и для принудительных, и для фоновых обновлений кэша; remote-фичу-гейтинг плагинов остаётся общим для всего запроса.

## Remote-сэндбокс: home, OS и deny-read по путям executor'а

Четыре PR доводят соблюдение политик в удалённых (executor) сценариях до соответствия фактическому окружению исполнения.

- [`#41204`](https://github.com/openai/codex/pull/41204) — домашняя директория executor'а теперь репортится в метаданные окружения, кешируется для выбранного turn-окружения и включается в sandbox-контексты файловой системы, включая `apply_patch`. Executor'ы, не репортящие home, остаются совместимыми.
- [`#41207`](https://github.com/openai/codex/pull/41207) — новое опциональное поле `platformOs` в серверных метаданных: локальные exec-серверы репортят `std::env::consts::OS`, legacy-серверы совместимы, когда поле отсутствует. Значение сохраняется в каждом выбранном turn-окружении, включая локальное.
- [`#41209`](https://github.com/openai/codex/pull/41209) — выравнивает deny-read политики с path-семантикой целевого executor'а: deny-корни и glob-матчеры готовятся из `PathUri`-контекста (включая executor-относительные рабочие директории и home-относительные паттерны), Windows-glob'ы сопоставляются case-insensitively с нормализованными разделителями (POSIX-матчинг остаётся byte-ориентированным для non-UTF-8 путей). Malformed-пути, несовместимые конвенции, неразрешённые home-относительные паттерны и невалидные glob'ы фейлятся закрыто (fail closed).
- [`#41196`](https://github.com/openai/codex/pull/41196) — на Windows deny-read glob'ы расширяются по защищённым директориям с сохранением файловой проверки; склеен с ним фикс, сохраняющий структурированные MCP tool/resource-ошибки в app-server-ответах (вместо стирания), и привязывающий кешированные Guardian-классификации к текущему local/root auth-состоянию, чтобы устаревшие оценки не могли авторизовать действия после смены permissions.

## Сохранение permission-профилей и защита от ослабления sandbox

PR [`#41192`](https://github.com/openai/codex/pull/41192) чинит TUI: восстановленные app-server-потоки могут нести permission-профили, которые нельзя без потерь выразить как legacy sandbox-mode override. Раньше отправка таких профилей как per-turn overrides могла отбросить их исходные детали. Теперь восстановленные профили отличаются от legacy per-turn overrides и сохраняются при routing'е turn'ов и смене рабочих директорий, а `/cd` отклоняется, если восстановленный профиль нельзя безопасно представить legacy sandbox-режимом (например, read-only профиль не «роняется» в ослабляющий override).

## Модели: изоляция tool-планов и reasoning у Ultra

Два PR стабилизируют поведение при смене/фолбэке модели.

- [`#41195`](https://github.com/openai/codex/pull/41195) — финализация tool-планов в `ToolRouter`: построение tool-реестров и видимых спеков идёт из явного `ModelInfo`, финализированный tool mode, code-mode имена, namespace-inventory и terminal/child-management capability хранятся на самом `ToolRouter`. Это исключает гонку, когда подготовка fallback-модели могла перезаписать метаданные до отправки запроса текущей модели.
- [`#41206`](https://github.com/openai/codex/pull/41206) — reasoning фолбэк становится model-aware: в метаданные модели добавляется опциональное поле `multi_agent_reasoning_effort`. Когда выбрана модель `Ultra`, используется поддерживаемая catalog-override, если она есть; иначе — `max`, затем наивысший поддерживаемый non-`ultra` effort, и наконец `medium` для моделей без уровней reasoning. Прочее поведение (включая маппинг `persistent` → `disabled`) не меняется.

## Учёт токенов сабагентов

PR [`#41183`](https://github.com/openai/codex/pull/41183) — токены из дочерних (включая вложенных сабагентов) агентов теперь катятся в usage корневой цели, а не теряются. Потраченное учитывается и при активном, и при idle progress-аккаунтинге, поэтому вложенные агенты вносят вклад в token-бюджеты; базлайны аккаунтинга сбрасываются при смене активной цели, а usage, записанный одновременно с checkpoint'ом, сохраняется.

## Служебное

- [`#41189`](https://github.com/openai/codex/pull/41189) / [`#41205`](https://github.com/openai/codex/pull/41205) — телеметрия: инструментация проверок размера escalated stdin-review и discovery MCP-инструментов у remote executor'а.
- [`#41191`](https://github.com/openai/codex/pull/41191) / [`#41194`](https://github.com/openai/codex/pull/41194) — стабилизация Guardian WebSocket и core fixture-тестов под медленным/высококонкурентным CI.

## Итоги для обновления

1. **MCP + расширения.** Если вы разрабатываете расширение Codex, реализуйте `ToolLifecycleContributor::on_mcp_tool_result` для инспекции или замены результатов MCP-инструментов (включая ошибки) до отправки модели.
2. **Optional MCP-серверы.** Задайте `mcp_optional_startup_grace_ms` (default `1000`) для более щедрой либо, при `0`, пер-server `startup_timeout_sec`-задержки.
3. **Каталоги плагинов.** Ошибки невалидного проекта теперь приходят через `marketplaceLoadErrors`, не скрывая рабочие каталоги; локальные marketplaces мержатся по-репозиторийно.
4. **Remote-сэндбокс.** Home и OS executor'а включены в sandbox-контексты, deny-read сопоставляется с path-семантикой executor'а и фейлится закрыто; cached permissions нельзя обойти устаревшей Guardian-классификацией.
5. **TUI.** Восстановленные permission-профили сохраняются, а `/cd`, не способный безопасно представить профиль, отклоняется.

Релиз сфокусирован на зрелости: MCP-пайплайн становится расширяемым, remote-execution и permissions — честнее к фактическому окружению, а расход токенов сабагентов перестаёт «прятаться» от бюджета.
