OpenAI выпустила [`rust-v0.150.0`](https://github.com/openai/codex/releases/tag/rust-v0.150.0) — minor-релиз Codex, в котором фокус сместился на TUI-сценарии: агенты теперь могут ссылаться друг на друга через `@`, `/copy` получил пикер целей, треды получают автоматические названия, а переключение permission modes и пересмотр Vim-редактирования добирают недостающие горячие клавиши.

Ниже — разбор GitHub Release и связанных PR: [`#40308`](https://github.com/openai/codex/pull/40308), [`#40315`](https://github.com/openai/codex/pull/40315), [`#39997`](https://github.com/openai/codex/pull/39997), [`#40492`](https://github.com/openai/codex/pull/40492), [`#40495`](https://github.com/openai/codex/pull/40495), [`#40471`](https://github.com/openai/codex/pull/40471), [`#39873`](https://github.com/openai/codex/pull/39873), [`#40521`](https://github.com/openai/codex/pull/40521), [`#40511`](https://github.com/openai/codex/pull/40511), [`#39837`](https://github.com/openai/codex/pull/39837), [`#40004`](https://github.com/openai/codex/pull/40004), [`#39993`](https://github.com/openai/codex/pull/39993).

## Управление задачами из терминала: `@`-упоминания и tools `codex_tui`

Релиз делает длинные многоагентные сессии управляемыми прямо из композера. PR [`#40308`](https://github.com/openai/codex/pull/40308) добавляет пространство инструментов `codex_tui`: агент через него может **перечислять, читать, ожидать, создавать, форкать, отправлять сообщения, переименовывать, архивировать и восстанавливать** другие задачи. Раньше TUI отклонял вызовы динамических app-server инструментов как неподдерживаемые, и агент не мог посмотреть или поменять состояние чужой сессии. Отбор исходит из ограниченных входов/ответов, а делегирование маршрутизируется через авторизованный локальный MCP-сервер с явными промптами одобрения и учётом managed MCP-политик; при подключении к старому app-server, который не поддерживает динамические инструменты, тред стартует без них.

Композер теперь знает о задачах и через [`#40315`](https://github.com/openai/codex/pull/40315): в popup упоминаний `@` появляются подходящие задачи активного треда (сначала из текущей рабочей директории). Выбранная задача уходит как ограниченная live-ссылка на тред, которую агент открывает инструментом `read_thread`:

```text
@ — открыть упоминания; среди сущностей выводятся и задачи Codex
(read задачи агент читает через read_thread)
```

Упоминания задач сохраняются в истории композера и переживают start/resume/fork треда.

## `/copy` с пикером целей

PR [`#39997`](https://github.com/openai/codex/pull/39997) убирает проблему «скопировал весь ответ, а нужен один блок». `/copy` теперь открывает пикер, где можно выбрать **весь ответ целиком**, отдельный fenced code block или blockquote из последнего ответа. Блоки кода подписаны языком, показывается превью содержимого, а при копировании отдельной цели сохраняются исходные пробелы и вложенный Markdown цитат. Пикер не трогает scrollback терминала и очередь ввода, не сбрасывает clipboard-аренду и не пишет скопированный контент в журнал сессии.

## Автоматические заголовки тредов и подсказки в `/rename`

Два PR закрывают назойливый ручной шаг — именование тредов. [`#40492`](https://github.com/openai/codex/pull/40492) даёт безымянным TUI-тредам мгновенный **временный** заголовок из первого сообщения пользователя, который затем асинхронно заменяется нормализованным сгенерированным названием. Генерация использует ограниченный эфемерный structured-запрос: сохраняет кастомный permission-профиль (иначе — read-only), отключает tools и MCP-серверы, а уведомления об авто-переименовании не попадают в транскрипт. Ручные переименования не стираются: авто-заголовок применяется только пока provisional-титул ещё актуален.

[`#40495`](https://github.com/openai/codex/pull/40495) дополняет это в `/rename`: при открытии промпта из последних значащих сообщений пользователя и ассистента генерируется подсказка, которая предзаполняет поле — но остаётся редактируемой, и введённый до завершения генерации текст не теряется. Устаревшие сгенерированные варианты (от другого треда) игнорируются.

## Markdown-ссылки как кликабельные лейблы

[`#40471`](https://github.com/openai/codex/pull/40471) улучшает терминальный вывод Markdown. В распознанных терминалах с поддержкой гиперссылок адрес выводится голубым с подчёркиванием, а повторяющийся URL прячется (виден как OSC 8 target). Для неизвестных терминалов, мультиплексоров, non-terminal вывода и пустых лейблов адрес остаётся видимым текстом, так что ссылка не теряется. OSC 8-цели сохраняются при переносе строк в таблицах и прозе, потоковых обновлениях, клиппинге транскрипта и скролле пейджера.

## Горячие клавиши: циклирование permission modes и dot-repeat в Vim

[`#39873`](https://github.com/openai/codex/pull/39873) добавляет в `tui.keymap.chat` два действия — `previous_permission_mode` и `next_permission_mode` — для цикличного перебора доступных встроенных permission modes. По умолчанию они не забиндины; назначенные комбинации применяются только к активной сессии (без записи в `config.toml`), а недоступные по managed-требованиям или проверкам безопасности режимы исключаются:

```toml
[tui.keymap.chat]
next_permission_mode = "ctrl+t"     # циклировать permission modes текущей сессии
previous_permission_mode = "ctrl+shift+t"
```

[`#40521`](https://github.com/openai/codex/pull/40521) доводит Vim-режим до полноценного редактирования: в normal mode привязывается `.` — повтор последней завершённой правки. Записываются семантические delete/change/replace/paste и insert-mode действия, поэтому повторы сохраняют движения, text objects, вставленный текст и editor-действия даже при смене keymap. Действие доступно как `vim_normal.repeat_last_change` в конфигурируемом keymap и в пикере с обработкой конфликтов кастомных биндингов.

## Новые `Interrupt`-хуки

[`#40511`](https://github.com/openai/codex/pull/40511) добавляет в hook-систему событие `Interrupt`: оно выполняется для активного top-level треда **до** того, как будет эмитится его abort-событие. Входы хука включают session, turn, транскрипт (перд этим flush-ится), рабочую директорию, модель и permission mode. Поддерживаются command- и MCP-обработчики, включая асинхронные команды, с дефолтным таймаутом в одну секунду и максимумом в три:

```toml
[hooks.Interrupt]
hooks = [{ type = "command", command = "python3 hook.py", statusMessage = "running interrupt hook" }]
```

Событие проброшено через конфигурацию, managed-requirements, app-server-уведомления, генерируемые схемы, аналитику и TUI-вьюхи хуков.

## Безопасность и доверие проектов

- **Untrusted-проекты и `AGENTS.md`** ([`#39837`](https://github.com/openai/codex/pull/39837)) — для непроверенных проектов больше не подхватываются project-scoped `AGENTS.md`-инструкции (user-level остаются). Уровень доверия проекта включён в ключ кэша инструкций, поэтому смена доверия на лету перезагружает применимые инструкции, а метаданные доверия сохраняются при runtime-обновлении конфигурации.
- **Managed deny-read** ([`#40004`](https://github.com/openai/codex/pull/40004)) — managed-правила запрета чтения путей хранятся отдельно и вливаются в обновлённые permission-профили: runtime-обновление permissions больше не может ослабить требование `deny_read`. Конфликтующие профили и legacy sandbox-политики отклоняются, то же ограничение применяется и в `command/exec` при запросе-специфичной sandbox-политике.

## Крас-акция credentials в app-server-журналах

[`#39993`](https://github.com/openai/codex/pull/39993) решает реальный риск утечки: журналы app-server могут сохраняться или уходить вместе с диагностикой. Появляется тип `RedactedString` — сохраняет сериализацию и строковый доступ, но в debug-выводе показывает `<redacted>`. Им оборачиваются bearer-токены model-провайдеров, header/query-значения, аргументы команд аутентификации и attestation-токены; JSON-RPC payload'ы ошибок и парсер/аутентификационные ошибки, способные эхо-повторить credentials, больше не логируются (сохраняются только безопасные код и категория). В комплекте — регрессионный тест, проверяющий, что credentials не оседают в персистентном SQLite и в поданных диагностических логах.

## MCP: bearer-токены в executor-окружениях и совместимость

Три PR чинят удалённый MCP в executor-сценариях. [`#39926`](https://github.com/openai/codex/pull/39926) сохраняет `bearer_token_env_var` для executor-owned HTTP MCP-серверов и резолвит его в окружении выбранного executor'а на каждый запрос; делегированные HTTP-заголовки получают executor-local ссылки на переменные окружения с отклонением отсутствующих/пустых/protected credential-переменных, а транспортный bearer остаётся совместимым с MCP redirect и OAuth. [`#39952`](https://github.com/openai/codex/pull/39952) переносит `required`-флаг с HTTP MCP-серверов, обнаруженных у выбранного executor'а: обязательный executor-MCP-сервер корректно ждёт старта, и его инструмент доступен уже на первом третe. [`#39979`](https://github.com/openai/codex/pull/39979) адресует старых executor'ов: capability `httpHeaderEnvVars` указывает, умеет ли executor резолвить env-backed заголовки; token делегируется только при поддержке, иначе резолвится в host-окружении, а executor-owned-серверы, требующие недоступных env-токенов, исключаются — совместимые host/executor-owned остаются рабочими.

## Исправления Windows, Unix и Amazon Bedrock

- **Windows sandbox** ([`#39971`](https://github.com/openai/codex/pull/39971)) — запуск elevated setup-хелпера выходил из-под контроля: sandbox-setup идёт на Tokio worker-треде без message loop, и `ShellExecuteExW` теперь запускается с `SEE_MASK_NOASYNC` (синхронная активация), сохраняя `SEE_MASK_NOCLOSEPROCESS` для отслеживания процесса-хелпера.
- **Unicode-пути и batch-алиасы** ([`#40570`](https://github.com/openai/codex/pull/40570)) — batch-алиасы на Windows ломались, когда в пути исполняемого файла были символы вне активной console code page. Теперь генерируются same-volume пути относительно batch-файла через `%~dp0`, а абсолютный путь остаётся fallback'ом для разных томов (протестировано на code page 437).
- **Unix shutdown** ([`#40460`](https://github.com/openai/codex/pull/40460)) — отсоединённый процесс, удерживающий терминал или переполнивший output-канал, больше не вешает остановку Tokio-runtime. Чтение/запись PTY переведены на nonblocking `AsyncFd`-readiness, вывод докачивается после закрытия receiver'а, при закрытии portable PTY stdin сохраняются очередь ввода и доставка EOF.
- **Amazon Bedrock** ([`#39804`](https://github.com/openai/codex/pull/39804), [`#39825`](https://github.com/openai/codex/pull/39825)) — Bedrock не поддерживает response items, требуемые multi-agent V2, поэтому каталог моделей приводится к `MultiAgentVersion::V1`; компакция переведена на `compaction_trigger`-элементы через `/v1/responses`, удалён устаревший выделенный протокол компакции, а remote-компакция по умолчанию выключена и явно включена только для OpenAI, Azure Responses и Amazon Bedrock.

## Итоги для обновления

1. **Задачи из TUI.** Ссылайтесь на другие задачи через `@` в композере (выбранный тред агент читает как `read_thread`), а для списка/чтения/ожидания/создания/форка/сообщений/переименования/архивации используйте tools `codex_tui`.
2. **Копирование.** `/copy` предлагает пикер: весь ответ, отдельные code block или blockquote — без повреждения whitespace и вложенного Markdown.
3. **Именование.** Треды получают временный, а затем сгенерированный заголовок; `/rename` предзаполняет поле подсказкой по диалогу.
4. **Ссылки.** В поддерживаемых терминалах Markdown-адреса становятся кликабельными лейблами (OSC 8), адрес прячется; в неизвестных терминалах URL остаётся видимым.
5. **Горячие клавиши.** Забиндите `next_permission_mode` / `previous_permission_mode` в `[tui.keymap.chat]` (действуют на активную сессию) и используйте `.` в Vim normal mode для повтора последней правки.
6. **Хуки.** Добавьте `[hooks.Interrupt]` через command/MCP-обработчик, если нужно выполнить действие при прерывании активного треда (таймаут до 3 секунд).

Минорный релиз `0.150.0` заметно приближает Codex к полноценной мультиагентной среде прямо из терминала, одновременно закрывая несколько классов проблем безопасности (доверие проектов, managed deny-read, наши credentials в логах) и доводя MCP/Windows/Bedrock до стабильного состояния.
