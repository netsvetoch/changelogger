Zed выпустил minor-релиз [`v1.15.0`](https://github.com/zed-industries/zed/releases/tag/v1.15.0). Это не pointer-only release: основной источник — GitHub Release и связанные PR. Главные пользовательские изменения — выбор базы для git-индикаторов через `git.diff_base`, drag-out файлов из Project Panel наружу на macOS и Linux Wayland, linked editing для custom elements в JSX/TSX и поддержка self-hosted Sweep Next Edit в OpenAI-compatible edit predictions.

Для разбора проверены release notes и реализации PR [`#61501`](https://github.com/zed-industries/zed/pull/61501), [`#61304`](https://github.com/zed-industries/zed/pull/61304), [`#58161`](https://github.com/zed-industries/zed/pull/58161), [`#61947`](https://github.com/zed-industries/zed/pull/61947), [`#58578`](https://github.com/zed-industries/zed/pull/58578), [`#53688`](https://github.com/zed-industries/zed/pull/53688), [`#51139`](https://github.com/zed-industries/zed/pull/51139), [`#60018`](https://github.com/zed-industries/zed/pull/60018), [`#60602`](https://github.com/zed-industries/zed/pull/60602) и [`#60535`](https://github.com/zed-industries/zed/pull/60535).

## `git.diff_base`: gutter и `git: diff` против merge base default branch

PR [`#61501`](https://github.com/zed-industries/zed/pull/61501) (с более ранней реализацией в [`#60398`](https://github.com/zed-industries/zed/pull/60398)) добавляет настройку `git.diff_base`. До релиза editor gutter, цвета статусов файлов и `git: diff` показывали только uncommitted-изменения относительно `HEAD`. Теперь можно смотреть все изменения текущей ветки относительно merge base с default branch репозитория.

```json
{
  "git": {
    "diff_base": "default_branch"
  }
}
```

Допустимые значения:

- `"head"` — прежнее поведение и дефолт в `assets/settings/default.json`;
- `"default_branch"` — tree diff merge-base → worktree (`git diff --merge-base`).

Тот же переключатель доступен в меню editor controls как **Diff Against Default Branch** и применяется live, без перезапуска.

Важные детали реализации из PR:

- статусы считаются по реальному merge-base-to-worktree diff: если локальная правка откатывает изменение ветки к содержимому base, файл показывается как clean;
- `BufferDiff` получил `DiffBaseKind` (`Head`, `Index`, `Oid`, `Custom`); hunk-level stage/restore активны только когда base — `Head` (`is_stageable()`), чтобы случайно не переписать уже закоммиченный код;
- в режиме `default_branch` stage/restore кнопок на hunks нет, но whole-file staging через Git Panel по-прежнему работает;
- `git::Diff` следует настройке; `git::DiffHead` всегда открывает diff против `HEAD`; `git::BranchDiff` переименован в `git::DiffBranch` (deprecated alias сохранён);
- remote host на старом server, который не знает `GetTreeDiff.includes_worktree`, деградирует до committed-only branch diff;
- если default branch не резолвится, поведение откатывается к HEAD.

Это полезно на feature-ветках: gutter и file colors сразу показывают полный diff к `main`/`master`, а не только незакоммиченные правки поверх последнего commit ветки.

## `gutter.git_gutter_width`: ширина git-индикаторов в пикселях

PR [`#61304`](https://github.com/zed-industries/zed/pull/61304) добавляет опциональную ширину полоски git hunks в gutter. Раньше ширина всегда считалась как `floor(0.275 * line_height)` (для deleted-hunk marker — `0.35 * line_height`), из-за чего на части шрифтов и DPI полоска получалась слишком тонкой или толстой, а hit target для клика по hunk оставался узким.

```json
{
  "gutter": {
    "git_gutter_width": 6
  }
}
```

`null` (дефолт) сохраняет прежнее масштабирование от line height. Значение в пикселях идёт и в отрисовку, и в hitbox hunks, так что более широкая полоска одновременно упрощает клик по stage/restore controls, когда они доступны.

## Drag-out файлов из Project Panel: macOS и Linux Wayland

Два связанных PR закрывают внешний drag из Project Panel:

- [`#58161`](https://github.com/zed-industries/zed/pull/58161) — native macOS drag session через AppKit: в pasteboard кладутся file URL, Finder и другие apps могут copy/move. Пути резолвятся только в момент начала drag gesture; remote и отсутствующие пути пропускаются. Внутренние GPUI drag/drop остаются под контролем приложения.
- [`#61947`](https://github.com/zed-industries/zed/pull/61947) — outbound drags на Wayland через `wl_data_source`. Автор PR проверял KDE/kwin 6.7.3: drag в Firefox, Dolphin и другие окна Zed.

Практически: файл или папку из Project Panel можно перетащить в Finder/Dolphin, браузер или другое приложение без copy path → paste.

## JSX/TSX: linked editing custom elements и Emmet в return/arrow bodies

PR [`#58578`](https://github.com/zed-industries/zed/pull/58578) чинит linked editing для custom element имён. В TSX grammar `linked_edit_characters` раньше содержал только `"."`, поэтому rename `Foo` → `custom-el` обрывался на дефисе и closing tag не зеркалился. Теперь:

```toml
linked_edit_characters = [".", "-"]
```

Переименование `<custom-el>` обновляет и opening, и closing tag целиком.

PR [`#53688`](https://github.com/zed-industries/zed/pull/53688) расширяет Emmet completion scopes в `javascript/overrides.scm` и `tsx/overrides.scm`: parenthesized expression внутри `return_statement` и body arrow function помечаются как `@element`. Раньше Emmet срабатывал в JSX-элементах, но не в типичных паттернах:

```tsx
const Card = () =>
  // Emmet completions работают здесь
  div.card;

function Page() {
  return (
    // и здесь
    section.hero > h1.title
  );
}
```

## Self-hosted Sweep Next Edit в OpenAI-compatible edit predictions

PR [`#51139`](https://github.com/zed-industries/zed/pull/51139) добавляет prompt format `sweep` и модель-путь `EditPredictionModel::SweepPrompt` для self-hosted [Sweep Next Edit](https://huggingface.co/sweepai/sweep-next-edit-1.5B). Это не просто новый пункт dropdown: Zed строит rewrite-window prompt (окно вокруг курсора, recent change history, related file excerpts), парсит rewritten window обратно в anchored edits и подавляет no-op rewrite.

`prompt_format: "infer"` распознаёт имена с `sweep-next-edit`, включая filename-style идентификаторы llama-server вроде `sweepai_sweep-next-edit-1.5B_sweep-next-edit-1.5b.q8_0.v2.gguf`.

Пример локального server и settings из PR:

```sh
llama-server \
  --hf-repo sweepai/sweep-next-edit-1.5B \
  --hf-file sweep-next-edit-1.5b.q8_0.v2.gguf \
  --ctx-size 8192 \
  --host 127.0.0.1 \
  --port 8080
```

```json
{
  "edit_predictions": {
    "provider": "open_ai_compatible_api",
    "open_ai_compatible_api": {
      "api_url": "http://127.0.0.1:8080/v1/completions",
      "model": "sweepai_sweep-next-edit-1.5B_sweep-next-edit-1.5b.q8_0.v2.gguf",
      "prompt_format": "infer",
      "max_output_tokens": 512
    }
  }
}
```

Можно задать `"prompt_format": "sweep"` явно. Перед отправкой Zed отклоняет reserved Sweep tokens в пользовательском контексте, чтобы не слать malformed request на self-hosted endpoint.

## `multiple_selections` key context

PR [`#60018`](https://github.com/zed-industries/zed/pull/60018) добавляет key context `multiple_selections`, когда в editor больше одного disjoint selection. Это позволяет вешать разные bindings на один shortcut:

```json
[
  {
    "context": "VimControl && !menu && multiple_selections",
    "bindings": {
      "z z": "editor::OpenSelectionsInMultibuffer"
    }
  }
]
```

С одним selection `z z` остаётся center-on-cursor (Vim), с несколькими — открывает selections в multibuffer. Условие выставляется в `Editor` key context, когда `selections.disjoint_anchors().len() > 1`.

## Project switcher: закрыть активный проект

PR [`#60602`](https://github.com/zed-industries/zed/pull/60602) показывает close button и на currently selected project. Раньше кнопку прятали на активном проекте, и закрытие требовало сначала переключиться на соседний. Теперь close активного проекта:

1. активирует уже открытый workspace соседа (local или remote);
2. иначе открывает соседа через host-aware `find_or_create_workspace`;
3. только если соседей не осталось — падает в empty workspace.

## Breaking: отдельная auth-путь для Copilot Chat и edit predictions

PR [`#60535`](https://github.com/zed-industries/zed/pull/60535) разделяет authentication paths для Copilot Chat и Copilot edit predictions. Это повышает устойчивость провайдера, но **существующим пользователям нужно заново пройти authenticate с Copilot** после обновления до 1.15.0.

## Другие заметные фиксы

Из полного release body стоит выделить практические стабилизационные пункты (без отдельного diff-разбора каждого):

- Agent: MCP servers снова появляются в новых project threads после открытия worktree ([`#62026`](https://github.com/zed-industries/zed/pull/62026)); MCP extension config dialogs больше не всплывают в чужих workspaces ([`#61882`](https://github.com/zed-industries/zed/pull/61882));
- bundled npm cache больше не растёт без bound и не съедает гигабайты диска ([`#61750`](https://github.com/zed-industries/zed/pull/61750));
- undo/redo операций Project Panel больше не отправляет в trash файлы с unsaved edits без confirmation ([`#62294`](https://github.com/zed-industries/zed/pull/62294));
- string-form lifecycle commands dev container выполняются через `/bin/sh -c` по Dev Container specification ([`#60792`](https://github.com/zed-industries/zed/pull/60792)); Docker Compose dev containers снова запускают configured entrypoints ([`#61897`](https://github.com/zed-industries/zed/pull/61897));
- semantic tokens от нескольких language servers перестали «перетирать» друг друга при refresh ([`#61735`](https://github.com/zed-industries/zed/pull/61735), [`#61795`](https://github.com/zed-industries/zed/pull/61795));
- regex search с assertions больше не отдаёт incomplete results ([`#62158`](https://github.com/zed-industries/zed/pull/62158));
- community/Zed Guild: IME flicker, Markdown horizontal scroll, channel tab icons, release notes `escape` на Windows с Vim/Helix и ряд UI-выравниваний — см. секцию Shipped by the Zed Guild в [release notes](https://github.com/zed-industries/zed/releases/tag/v1.15.0).

## Кому имеет смысл обновляться сразу

- тем, кто работает в long-lived feature branches и хочет gutter/`git: diff` относительно `main`, а не только uncommitted delta к `HEAD` — `git.diff_base`;
- macOS и Wayland-пользователям, которым нужен drag файлов из Project Panel в Finder/Dolphin/браузер;
- frontend-разработчикам на JSX/TSX с custom elements и Emmet;
- тем, кто self-host'ит Sweep Next Edit через OpenAI-compatible completions API;
- пользователям Copilot — запланируйте повторный login после апдейта.
