[`pi`](https://github.com/earendil-works/pi) выпустил minor-релиз [`v0.84.0`](https://github.com/earendil-works/pi/releases/tag/v0.84.0). Для интерактивной работы это релиз про TUI и отображение Markdown: experimental fullscreen mode с sticky editor/footer и независимым scroll transcript, themed Mermaid и terminal-friendly LaTeX. Для конфигурации моделей — free-form `samplingParams`, opt-in vLLM `thinking_token_budget` и встроенный Baseten. Для интеграторов — experimental remote-session client (`PiClient` / Unix transport) и заметный набор breaking changes вокруг `message_update`, header null-markers и provider catalog refresh.

## Fullscreen TUI: sticky dock и отдельный scroll transcript

В settings появилось поле `tuiMode` со значениями `"regular"` (default) и experimental `"fullscreen"`. Режим можно задать при старте CLI или переключить в runtime через `/settings` — изменения из `/settings` применяются сразу; `--tui-mode` перекрывает setting только на текущий запуск.

```bash
pi --tui-mode fullscreen
```

```json
{
  "tuiMode": "fullscreen",
  "fullscreenScrollbar": "auto"
}
```

В fullscreen transcript скроллится отдельно от sticky dock: editor, status, widget и footer остаются на месте. Scrollbar transcript настраивается через `fullscreenScrollbar`:

| Значение         | Поведение                                     |
| ---------------- | --------------------------------------------- |
| `auto` (default) | Показывается временно во время scroll         |
| `always`         | Резервирует правую колонку и остаётся видимым |
| `hidden`         | Скрыт; в regular mode setting не действует    |

Дополнительно: draggable scrollbar, page scrolling и навигация по marked messages, stacked transient notifications, optional theme color `scrollbarThumb` (fallback — `selectedBg`). Default mouse wheel step в fullscreen уменьшен с трёх строк до одной. Часть клавиш навигации transcript пересекалась с editor: для Home/End/PageUp/PageDown в editor добавлены Ctrl-модифицированные bindings ([#7574](https://github.com/earendil-works/pi/issues/7574)).

## Mermaid, LaTeX и display-only Markdown transformers

Интерактивный transcript умеет рендерить supported Mermaid-диаграммы themed Unicode-графикой. Режим задаётся `markdown.mermaid`:

| Значение              | Смысл                             |
| --------------------- | --------------------------------- |
| `off`                 | Не рендерить                      |
| `final`               | Рендер после завершения сообщения |
| `streaming` (default) | Рендер и во время streaming       |

```json
{
  "markdown": {
    "codeBlockIndent": "  ",
    "mermaid": "streaming"
  }
}
```

Параллельно унаследованный TUI Markdown получил terminal-friendly Unicode-рендер LaTeX-выражений (см. [TUI Markdown](https://github.com/earendil-works/pi/blob/v0.84.0/packages/tui/README.md#markdown)).

Для extensions добавлен chainable hook `pi.registerMarkdownTransformer()` ([#7231](https://github.com/earendil-works/pi/pull/7231)). Transformers идут в порядке загрузки расширений, каждый получает Markdown предыдущего; после цепочки Pi рисует результат встроенным renderer. Контекст:

- `messageType`: `"user" | "assistant" | "assistant-thinking"`
- `isStreaming`: partial assistant updates vs финальные/restored
- `availableWidth`: точная ширина terminal columns под контент

```ts
pi.registerMarkdownTransformer((markdown, { messageType, isStreaming }) => {
  if (isStreaming || messageType === "assistant-thinking") return markdown;
  return markdown.replaceAll("-->", "→");
});
```

Hook **display-only**: исходное сообщение в session/model context не меняется. При throw Pi сохраняет уже полученный Markdown и продолжает со следующим transformer. Transformers должны быть синхронными и дешёвыми: они вызываются на новых user messages, assistant streaming updates, restore session и смене ширины терминала.

## `AGENTS.override.md`: per-directory подмена context files

Раньше Pi собирал `AGENTS.md` / `CLAUDE.md` из `~/.pi/agent/`, родительских каталогов и cwd. Теперь, если в каталоге лежит `AGENTS.override.md`, для **этого** каталога загружается именно override вместо `AGENTS.md`/`CLAUDE.md`; context files из других директорий по-прежнему layer'ятся ([#7681](https://github.com/earendil-works/pi/pull/7681)).

Типичный кейс — monorepo: в корне общие правила, а в `packages/frontend/` — полный override без «склейки» с локальным `AGENTS.md`.

```text
repo/
  AGENTS.md                 # общий слой
  packages/api/AGENTS.md
  packages/frontend/
    AGENTS.override.md      # заменяет AGENTS.md/CLAUDE.md только здесь
```

Отключить context files по-прежнему можно флагами `--no-context-files` / `-nc`.

## `samplingParams` и vLLM `thinking_token_budget`

В model definition (`models.json`, model overrides, extension providers, stream options) появилось free-form поле `samplingParams`. Объект **verbatim** мержится в request body после полей, которые Pi выставляет сам, поэтому его ключи побеждают. Это путь для engine-specific параметров вроде llama.cpp `min_p` / `dry_multiplier` или vLLM `top_k` без отдельной поддержки каждого поля в schema Pi ([#7568](https://github.com/earendil-works/pi/pull/7568)).

```json
{
  "id": "deepseek-v4-flash",
  "samplingParams": {
    "temperature": 1.0,
    "top_p": 0.95,
    "top_k": 0,
    "min_p": 0.0
  }
}
```

Применяется только к OpenAI-compatible API: `openai-completions`, `openai-responses`, `azure-openai-responses`; остальные API игнорируют поле. В `modelOverrides` `samplingParams` мержится **per key** с base model.

Отдельно для reasoning-моделей на vLLM: reasoning и final answer делят один `max_tokens`, и длинный thinking мог съесть весь budget, после чего agent-loop завершал run как будто задача закончена. Opt-in compat-флаг `supportsThinkingTokenBudget` прокидывает top-level `thinking_token_budget` в `openai-completions`, с clamp так, чтобы оставался reserve на answer (`MIN_ANSWER_TOKENS`). Флаг независим от `thinkingFormat`: один vLLM-сервер может отдавать zai/qwen/chat-template модели с разным wire format thinking ([#7638](https://github.com/earendil-works/pi/pull/7638)). Default — off.

Для OpenAI-compatible streams без `finish_reason` добавлен `compat.supportsFinishReason` (default `true`). При `false` Pi сам выводит `stop` или `toolUse` по концу stream.

## Baseten и `AI_AGENT=pi`

Встроенный provider **Baseten**: auth через `BASETEN_API_KEY`, provider id `baseten`, default model `zai-org/GLM-5.2`. В таблице API keys он стоит рядом с Fireworks/Together.

CLI и RPC entry points выставляют в child-process environment `AI_AGENT=pi` — generic attribution для tooling рядом с уже существующим `PI_CODING_AGENT=true` ([#7493](https://github.com/earendil-works/pi/pull/7493)).

## Experimental remote sessions: `PiClient` и protocol

Добавлены experimental remote-session client APIs ([#7344](https://github.com/earendil-works/pi/pull/7344), [#7348](https://github.com/earendil-works/pi/pull/7348), [#7371](https://github.com/earendil-works/pi/pull/7371), [#7409](https://github.com/earendil-works/pi/pull/7409)):

- transport-neutral `PiClient` (length-prefixed CBOR, без Node-specific imports в root package);
- protocol package и Unix-socket transport на subpath `@earendil-works/pi-client/unix`;
- coding-agent controller `RemoteSession` с transcript reducers (`@earendil-works/pi-coding-agent/client`).

```ts
import { PiClient } from "@earendil-works/pi-client";
import { createUnixTransportFactory } from "@earendil-works/pi-client/unix";

const client = new PiClient({
  transportFactory: createUnixTransportFactory({ path: "/tmp/pi.sock" }),
});

await client.connect();
const session = await client.createSession({ cwd: "/workspace" });
const unsubscribe = session.subscribe(snapshot => render(snapshot));
await session.prompt("Inspect this project");
unsubscribe();
```

Один connection — несколько sessions; acquisition через exclusive/shared leases (`createSession` → exclusive, `attachSession` → shared). Auto-reconnect нет: после disconnect нужен явный `reconnect()`. Metadata list — durable `SessionMetadata`; runtime phase/model/thinking/attachment/lock живут в acquired `SessionSnapshot`, а не в list summary ([#7708](https://github.com/earendil-works/pi/pull/7708)).

## Agent loop: `shouldStopAfterTurn`

В `AgentOptions` / `AgentLoopConfig` появился `shouldStopAfterTurn` ([#7367](https://github.com/earendil-works/pi/pull/7367)). Hook вызывается после `turn_end`, когда assistant response и tools уже нормально завершились. `true` → emit `agent_end` и выход **до** polling steering/follow-up queues и до следующего LLM call. Он не abort'ит provider stream, не отменяет running tools и не меняет stop reason assistant message.

```ts
const stream = agentLoop(
  prompts,
  context,
  {
    model,
    convertToLlm,
    shouldStopAfterTurn: async ({
      message,
      toolResults,
      context,
      newMessages,
    }) => {
      return shouldCompactBeforeNextTurn(context.messages);
    },
  },
  undefined,
  models.streamSimple.bind(models)
);
```

## Breaking changes, которые стоит проверить до обновления

### JSON/RPC `message_update` — только deltas

События `message_update` больше не несут cumulative `message` и `assistantMessageEvent.partial`. Остаются deltas `assistantMessageEvent`. Клиенты, которым нужен partial message, собирают deltas между `message_start` и `message_end`; authoritative остаётся `message_end` ([#7290](https://github.com/earendil-works/pi/issues/7290)). Это убирает quadratic growth output на длинных stream.

### Headers: `string | null` и deletion markers

`ModelRegistry.getApiKeyAndHeaders()` возвращает `ProviderHeaders` со значениями `string | null` и **сохраняет** `null` как marker удаления header. Extensions, которые инспектируют headers, обязаны обрабатывать `null`; при forward в pi-ai streams — пропускать unchanged. Иначе placeholder OpenAI credentials могут уехать через Cloudflare AI Gateway ([#7030](https://github.com/earendil-works/pi/issues/7030)).

Интерфейс `ModelsStreamTransforms` переименован в `ModelsRequestTransforms`: header transformation теперь применяется ко всем authenticated provider requests, не только к stream.

### `ModelRegistry.refresh` / `setRuntimeApiKey`

- `ModelRegistry.refresh()` принимает `ModelsRefreshOptions` и возвращает `ModelsRefreshResult` (cancellation и provider errors больше не discard'ятся).
- `ModelRuntime.setRuntimeApiKey()` принимает auth cancellation options, а не catalog refresh options. Remote freshness — отдельный вызов `refresh({ providers: [providerId], signal })`.
- OAuth `refreshToken(credentials, signal)` в config-form extensions обязан принимать и honor'ить concrete abort signal.

### Provider refresh: `context.stored` + `context.publish()`

Прямой доступ к store в dynamic provider refresh заменён на read-only snapshot `context.stored` и generation-checked `context.publish()`.

Providers через `createProvider({ fetchModels })` **не** требуют migration catalog publication: по-прежнему return models + `registerProvider`; `createProvider()` сам владеет restore/persist/in-memory publish.

Handwritten native `Provider.refreshModels()` нужно переписать:

```ts
// Before
refreshModels: async (context) => {
  const stored = await context.store.read();
  if (stored) currentModels = stored.models;
  if (!context.allowNetwork) return;

  const refreshed = await fetchModels(context.signal);
  currentModels = refreshed;
  await context.store.write({ models: refreshed, checkedAt: Date.now() });
},

// After
refreshModels: async (context) => {
  if (context.stored) {
    const restored = context.stored.models;
    if (!(await context.publish({
      update: () => { currentModels = restored; },
    }))) return;
  }
  if (!context.allowNetwork) return;

  const refreshed = await fetchModels(context.signal);
  if (context.signal.aborted) return;
  await context.publish({
    persist: { models: refreshed, checkedAt: Date.now() },
    update: () => { currentModels = refreshed; },
  });
},
```

В `publish()`: omit `persist` — storage без изменений; `ModelsStoreEntry` — write; `persist: null` — delete. Config-form callbacks, которые только return models, не меняются: Pi публикует returned list сам.

### pi-agent-core harness v4 / v2 default export

- Inherited harness session model заменён на v4 lane-based `Session`, `SessionStorage`, `SessionRepo` (durable operation records, global facts, shared sequence numbers, tree-scoped lane views).
- v2 session и `AgentHarness` API promoted из experimental entrypoint в default export; experimental subpaths удалены.
- Legacy JSONL и in-memory repository API сняты: используйте `JsonlSessionRepo` / `InMemorySessionRepo` под контракт `SessionRepo`.
- Custom harness FS обязан реализовать `FileSystem.renameFile()` для atomic JSONL publication (same-filesystem replacement, [#7707](https://github.com/earendil-works/pi/pull/7707)).

## Заметные fixes (коротко)

Релиз закрывает длинный хвост runtime/TUI/provider багов; из прикладных:

- path-containing `find` globs на Windows ([#6817](https://github.com/earendil-works/pi/issues/6817)); Git Bash/MSYS/Cygwin/WSL drive paths в file tools ([#7064](https://github.com/earendil-works/pi/issues/7064), [#7547](https://github.com/earendil-works/pi/issues/7547));
- messages, поставленные в очередь во время manual `/compact`, уходят после compaction, а не падают; race manual vs threshold auto-compaction ([#7370](https://github.com/earendil-works/pi/pull/7370));
- truncated responses ниже intended output limit → compact + one retry вместо немедленного end run ([#7540](https://github.com/earendil-works/pi/pull/7540));
- bare exact `--model` id, общий у нескольких providers: sole authenticated provider или явная ambiguity error ([#7327](https://github.com/earendil-works/pi/issues/7327));
- standalone x64 binaries без требования Haswell AVX2/BMI2 — baseline Bun runtime ([#7390](https://github.com/earendil-works/pi/pull/7390));
- login больше не зависает, если catalog refresh stalled: local credential consistency отделён от bounded background freshness ([#7027](https://github.com/earendil-works/pi/issues/7027));
- `/scoped-models` и `/model <name>` работают с cache, не ждут remote catalog;
- oversized images из tools проходят auto-resize ([#7330](https://github.com/earendil-works/pi/pull/7330));
- dependency bumps `undici` 8.9.0 и `brace-expansion` 5.0.9 под несколько GHSA.

## Что проверить при обновлении

1. **RPC/JSON clients:** пересоберите partial assistant message из deltas `message_update`; не ждите cumulative `message` / `.partial`.
2. **Extensions с headers:** обрабатывайте `null` в `ProviderHeaders`; forward markers as-is.
3. **Custom providers:** `createProvider({ fetchModels })` можно не трогать; handwritten `refreshModels` — на `context.stored` + `context.publish()`.
4. **Harness integrators:** v4 `SessionRepo` / `JsonlSessionRepo`, default export v2 `AgentHarness`, обязательный `renameFile()`.
5. **TUI users:** попробуйте `pi --tui-mode fullscreen` или `/settings` → TUI mode; при необходимости `fullscreenScrollbar` и `markdown.mermaid`.
6. **Monorepo context:** положите `AGENTS.override.md` туда, где нужен полный replace локальных instructions.
7. **Local/OpenAI-compatible engines:** вынесите engine-specific sampling в `samplingParams`; для vLLM reasoning включите `supportsThinkingTokenBudget` осознанно.
8. **Baseten:** `BASETEN_API_KEY` + provider `baseten`.
