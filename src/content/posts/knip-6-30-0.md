Вышел минорный релиз [Knip 6.30.0](https://github.com/webpro-nl/knip/releases/tag/knip%406.30.0) — инструмента для поиска неиспользуемых файлов, зависимостей и exports в JavaScript- и TypeScript-проектах. В этой версии появляется SARIF-reporter для GitHub Code Scanning, новый issue type `catalogReferences` для битых `catalog:` ссылок, более точный учёт catalog в `pnpm dlx` и scoped-запусках, анализ production type-зависимостей по опубликованным `.d.ts`, а также правки вокруг SCSS `url()`, Svelte template imports и inline dynamic import loaders.

Источники: [GitHub Release](https://github.com/webpro-nl/knip/releases/tag/knip%406.30.0), [compare 6.29.0…6.30.0](https://github.com/webpro-nl/knip/compare/knip%406.29.0...knip%406.30.0), коммиты [SARIF](https://github.com/webpro-nl/knip/commit/ce11cf5d4), [catalogReferences](https://github.com/webpro-nl/knip/commit/b2b86c3e5), [pnpm dlx catalog](https://github.com/webpro-nl/knip/commit/102189a1a), [scoped catalog](https://github.com/webpro-nl/knip/commit/f0365bae0), [script catalog](https://github.com/webpro-nl/knip/commit/9b3ab3778), [published types](https://github.com/webpro-nl/knip/commit/87d713e52), [SCSS url](https://github.com/webpro-nl/knip/commit/cbe13bf87), [workspace deps](https://github.com/webpro-nl/knip/commit/a75309eda), [Svelte](https://github.com/webpro-nl/knip/commit/aa303fb04), [loaders](https://github.com/webpro-nl/knip/commit/b90a299e2), а также PR [#1879](https://github.com/webpro-nl/knip/pull/1879), [#1908](https://github.com/webpro-nl/knip/pull/1908), [#1910](https://github.com/webpro-nl/knip/pull/1910), [#1911](https://github.com/webpro-nl/knip/pull/1911) и [#1912](https://github.com/webpro-nl/knip/pull/1912). ## SARIF reporter для Code Scanning

В список built-in reporters добавлен `sarif`. Он пишет JSON по схеме SARIF 2.1.0: driver `knip` с текущей версией, rules вида `knip/<issueType>` (например `knip/exports`, `knip/dependencies`) и results с `physicalLocation` (relative POSIX path + line/column). Severity Knip (`error` / `warn` / остальное) мапится в SARIF `error` / `warning` / `note`.

```bash
knip --reporter sarif > knip.sarif
```

Документация сразу показывает интеграцию с GitHub Code Scanning: upload через `github/codeql-action/upload-sarif@v4` с `if: always()`, чтобы отчёт попал в security tab даже при non-zero exit Knip. CLI help теперь перечисляет reporters так: `symbols`, `compact`, `codeowners`, `cycles`, `json`, `codeclimate`, `markdown`, `disclosure`, `github-actions`, `sarif`.

## `catalogReferences`: битые `catalog:` ссылки

Раньше Knip умел находить **неиспользуемые** catalog entries (`catalog`). Теперь есть второй issue type — `catalogReferences` («Unresolved catalog references»): если в `package.json` workspace стоит `"picocolors": "catalog:"` или `"lodash": "catalog:tools"`, а выбранный catalog такой пакет не определяет, issue указывает на consuming `package.json`, а не на файл catalog.

Оба типа входят в shortcut `--dependencies`:

```bash
knip --include catalog,catalogReferences
knip --exclude catalog,catalogReferences
knip --dependencies
```

В schema/config можно включать и выключать `catalogReferences` как отдельное правило. Auto-fix по-прежнему удаляет только unused catalog entries; unresolved references только репортятся — их нужно починить в манифесте или catalog-файле.

## Catalog в `pnpm dlx` / `pnpx` и в scoped runs

Resolver `pnpm dlx` / `pnpx` теперь распознаёт protocol `@catalog:` внутри package specifier и регистрирует catalog reference рядом с optional dependency. Покрыты формы из fixtures:

```json
{
  "scripts": {
    "default": "pnpm dlx sherif@catalog:",
    "named": "pnpm dlx --silent 'typescript@catalog:tools'",
    "scoped": "pnpx \"@scope/cli@catalog:\"",
    "package": "pnpm --package=@scope/tool@catalog:tools dlx sherif@catalog:"
  }
}
```

В тесте для такого workspace unused остаются только `default.lodash` и `tools.unused`; пакеты, на которые ссылаются dlx-скрипты, catalog больше не помечает как мёртвые.

Отдельно починен scoped-запуск (`--workspace` / `-W`). Catalog counselor теперь:

1. обходит **все** available workspaces, а не только выбранные, чтобы `catalog:` из соседних package.json удерживали shared catalog entry;
2. для workspaces вне текущего scope дополнительно парсит scripts и вытаскивает catalog inputs из `pnpm dlx` / похожих команд.

Практический эффект: `knip --workspace .` (или один leaf-пакет) не должен ложно объявлять unused catalog entry, который реально используется в другом workspace того же monorepo.

## Scoped `--workspace` подтягивает dependency workspaces

Семантика `-W` / `--workspace` расширена. Раньше в scope попадали target, ancestors и dependents. Теперь ещё и **dependency workspaces** — пакеты, от которых зависит выбранный workspace (транзитивно по workspace graph).

Документация формулирует три причины:

- ancestors могут держать зависимости, которыми пользуется linted workspace;
- dependency workspaces могут отдавать configuration/source (например shared `tsconfig` package);
- dependents могут импортировать exports linted workspace.

Fixture `tsconfig-package-extends` показывает сценарий: client extends `@fixtures/tsconfig-package/app.json`, тот extends `@fixtures/tsconfig-base/base.json` с `"types": ["chrome"]`. При `-W @fixtures/workspaces-tsconfig-package-extends__client` в `includedWorkspaceDirs` попадают `packages/tsconfig` и `packages/tsconfig-base`, а `packages/ignored` (не на dependency path) — нет; `@types/chrome` не уходит в false-positive unused devDependency.

## Production types: зависимости из опубликованных `.d.ts`

В strict production mode Knip перестаёт опираться только на type-only source imports. Новый анализатор `get-published-type-dependencies` читает **уже собранные** declaration files, которые пакет реально отдаёт потребителям:

- entry points из `types` / `typings` / `main` (с маппингом `.js→.d.ts`, `.mjs→.d.mts`, `.cjs→.d.cts`) и fallback `index.d.ts`;
- targets из `typesVersions`;
- type-условия в `exports` (`types`, `types@…`);
- overrides из `publishConfig` для `main` / `exports` / `types` / `typings` / `typesVersions`.

Если зависимость видна в этом public type graph, в strict mode она считается production usage и должна жить в `dependencies` или required `peerDependencies`, а не в `devDependencies`. И наоборот: type-only import только в source по-прежнему может оставаться в `devDependencies`.

Ограничения из docs и кода:

- private workspaces и пакеты с `publishConfig.directory` не анализируются этим путём;
- Knip следует **существующим** `.d.ts`, а не угадывает types из исходников до `tsc`.

Это закрывает #1909 / PR #1912 и меняет guidance в `handling-issues.mdx` (секция Production types).

## SCSS: assets из `url()`

Встроенный SCSS compiler раньше извлекал только `@use` / `@import` / `@forward`. Теперь regex также ловит `url(...)` и превращает статические локальные пути в synthetic imports:

```scss
.hero {
  background-image: url("./assets/used.jpg");
}
```

Учитываются double/single/unquoted формы и query/fragment (`./query.jpg?v=1#image` → `./query.jpg`). Игнорируются absolute `/…`, protocol-relative `//…`, external `https:`, `data:`, empty, Sass variables (`$asset`), interpolations `#{…}`, а также URL внутри строк и комментариев. Неиспользуемый `assets/unused.jpg` остаётся кандидатом на unused file.

## Svelte: dynamic import в template markup

Built-in Svelte compiler дополнен `dynamicImportsWithinTemplate`: из markup (вне `<script>` / `<style>` и HTML-комментариев) вытаскиваются literal `import('…')` внутри `{…}`-выражений — handlers, `{#await import(...)}`, nested expressions, template interpolations, import attributes.

```svelte
<button onclick={() => import('./Handler.svelte')}>handler</button>

{#await import('./AwaitSingle.svelte') then { default: C }}
  <C />
{/await}
```

Строки вроде `import('./Removed.svelte')` в `<code>`, attributes без expression и в комментариях **не** считаются references: fixture помечает только `Removed.svelte` как unused file среди 18 обработанных.

## Inline dynamic import loaders: только default export

Для паттерна lazy-route / code-split loader Knip вводит import flag `LOADER` и synthetic identifier `__loader-default`. Когда call expression получает inline arrow с `import('…')` (в том числе `async () => await import(...)`), reference к target-модулю считается loader-import:

```ts
const Dashboard = deferRoute(() => import("./pages/dashboard.js"));
const Settings = router.lazy(() => import("./pages/settings.js"));
const Terms = deferRoute(() =>
  import("./pages/terms.js").then(m => ({ default: m.TermsPanel }))
);
```

Если у target есть `default` export, loader «потребляет» только его: named exports вроде `unusedWidget` / `unusedAvatar` / `unusedToggle` остаются unused. Если default нет, поведение ближе к opaque import. Явный `.then(m => ({ default: m.TermsPanel }))` не является pure loader-arrow body — там named usage обрабатывается отдельно; `clause` в `terms.js` по-прежнему может попасть в unused exports.

## Плагины: oxlint Vite+, remark, Stryker, Vitest

Несколько точечных правок plugins:

**Oxlint + Vite+ (`jsPlugins` как object).** Plugin oxlint читает не только строковые `jsPlugins`, но и object form с полем `specifier`:

```ts
export default defineConfig({
  lint: {
    plugins: ["unicorn", "typescript"],
    jsPlugins: [
      "eslint-plugin-regexp",
      { name: "e18e", specifier: "@e18e/eslint-plugin" },
    ],
  },
});
```

**Remark.** Резолв имён плагинов приведён к семантике `load-plugin` / `pluginPrefix: 'remark'`: unscoped `pkg-a` → предпочитает `remark-pkg-a`, fallback на `pkg-a`; scoped `@scope/pkg-b` → `@scope/remark-pkg-b` или raw; local path остаётся `toDeferResolve`; missing placeholder не создаёт ложный unlisted. Выбор кандидата смотрит на реальные keys в dependencies/devDependencies манифеста.

**Stryker.** Plugin понимает CLI `stryker run <config>` и TS-конфиги: `stryker run --incremental stryker.custom.conf.ts` регистрирует `stryker.custom.conf.ts` как config input, откуда читаются `testRunner` / `checkers` (`@stryker-mutator/tap-runner`, `@stryker-mutator/typescript-checker`).

**Vitest.** При вызове functional Vite config больше не передаётся несуществующий `command: 'dev'` — только `'serve' | 'build'`, чтобы конфиги, которые бросают на unsupported command, не ломали plugin load.

## Прочие изменения

- `Track only enabled workspace plugins` — `enabledPluginsMap` стал sparse `Partial<Record<…>>`: в map попадают только включённые plugins, а не полный false-map по всем known plugins.
- Внутренние perf-правки: compile gitignore negations once, cache Node test script detection, simplify workspace assembly.
- `Remove tsc from ignoreBinaries` — только в root `knip.json` самого monorepo Knip, не изменение default ignore list продукта.
- Документация docs-сайта переведена на Starlight Blog plugin; sponsors/logos обновлены.

## Обновление

```bash
pnpm add -D knip@6.30.0
pnpm knip
```

После обновления имеет смысл:

1. если нужен Code Scanning — добавить `knip --reporter sarif > knip.sarif` в CI;
2. в monorepo с pnpm/Yarn/Bun catalogs прогнать `knip --include catalog,catalogReferences` и поправить битые `catalog:` ссылки;
3. в library-пакетах со strict production mode сверить, не «переехали» ли type-зависимости, видимые из published `.d.ts`, из `devDependencies` в `dependencies`/`peerDependencies`;
4. в Svelte- и SCSS-проектах убрать ручные ignores для template dynamic imports и локальных `url()` assets, если они были нужны только из-за слепых зон анализа.
